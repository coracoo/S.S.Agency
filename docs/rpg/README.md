# 可选回合制 RPG 试作

这是独立新模式，默认主场景仍为 `scenes/v3/title.tscn`。旧探索、卡牌战、素材、xlsx 内容管线及独立 3D 预览均保留。这里的四张技能卡是固定技能按钮，没有抽牌、共享牌库或共享行动点。

## 实际入口

1. 启动项目，在原标题选择「回合制 RPG 试作」
2. 准备页「六选三 / 成长装备」查看六职业并确认三人草稿，再明确「新开连战 · L5自选三人」
3. 依次进入疾行＋守盾、疾行＋咒术，第二场后手动点击明确的休息点，最后挑战棺守
4. 「继续安全档」恢复最后已提交的安全状态；失败重试回到同一战前快照，不重掷种子、不赠药
5. 「独立 Boss 测试 · 满状态」是单独新局测试，不能将其成绩当作完整连战
6. 「进入原参道探索」是显式选择的新模式探索适配入口；未选择新模式时原标题/委托沿用旧战斗
7. 原探索右上角「RPG整备 / 道具」保存当前世界并打开战外菜单；第二战后的回廊明确显示「RPG休息 / 整备」。菜单和「继续安全档」不会自动恢复资源，只有点击「休息 · 全员恢复」才恢复六人HP/MP，库存不补
8. 首战后的安全探索可用战外道具，休息/编队/换装/分支仍限定准备或休息点。战斗、待战、败北待重试和仪式期间均不允许战外用药
9. 菜单「返回原探索 · 已保存」保留位置、朝向、线索、对话标记和原仪式顺序；探索存档不能从菜单直接跳下一战。原标题→RPG→继续安全档返回保存场景，整备入口仍可用；写失败留在原场景或菜单，可原地重试

直接场景入口：`scenes/rpg/launcher.tscn`。不要直接打开 `battle.tscn` 期待自动生成战斗：它需要准备页建立的战前上下文。独立 3D 预览为 `scenes/preview/act01_approach_3d.tscn`，按 1/2 切镜头、C 显示二维比例参照、H 隐藏说明、R 复位。

新模式只写 `user://rpg_v1/`，不迁移/覆盖/删除旧 `user://progress.json` 或构筑档。新局确认只替换 RPG 安全档。保存失败明确显示错误，并可再次保存；未成功持久化前不发经验/剧情。

## 规则与内容

- 六职业：守卫、剑士、游侠、法师、治疗、控制；六选三共20种，无重复队员
- 独立HP/MP、按速度每轮各一个行动槽；24个固定技能，L1/L2/L3解锁。六人与队伍共享等级1–10；升级需100L经验
- L5标准装备已计入属性。脱装/降上限会钳制资源，穿回/升上限不免费治疗
- L6开始每人免费选择一条目录分支，L9强化同一条；不增加技能卡位或CD变化
- 首测两普通战各40XP、Boss120XP；胜利链路共200XP，仍为L5。失败/未完成不领取未赢遭遇奖励
- 初始治疗药3、魔力药1、复苏药1、净化粉1。HP/MP/库存跨战继承，只有明确休息回复HP/MP，休息不补药
- 战斗与预览来自唯一模型；预览不抽随机。敌方意图与Boss锁定目标/打断/不可打断提示直接读取模型事件
- 六职业复用凛音/薄荷两套既有美术，敌人复用现有素材。没有六套新立绘或Live2D/Cubism交付

完整数值与机制见[规格](../superpowers/specs/2026-09-30-rpg-combat-design.md)，验证事实与覆盖边界见[验证报告](verification-2026-09-30.md)。新 JSON 位于 `data/rpg/`，不修改旧 xlsx 管理的数据。

## 隔离验证

从仓库根运行，Godot 4.7.2（可用 `--godot /path/to/godot` 或 `GODOT_BIN`）。首次克隆、删除导入缓存或资源发生变化时，首个Godot验证命令必须带 `--import`；它在隔离预检成功后先导入资源和全局脚本类。后续增量验证可省略 `--import`，不提交 `.godot/` 或本次生成的导入侧文件：

```bash
python3 -m unittest tools.rpg.test_run_checks
python3 tools/rpg/run_checks.py --suite all --import --legacy
python3 tools/rpg/run_checks.py --suite acceptance --sweep both --output-dir /tmp/ssa-rpg-matrix
```

Python runner 为每次运行建立临时XDG/APPDATA目录；先由真实Godot确认实际 `user://` 是其子目录，再执行任何导入/测试。导入、每个测试、三个旧测试的退出码及 `SCRIPT ERROR`/`ERROR` 均检查，Godot打印PASS但发生脚本错误仍会失败。`--legacy` 依次执行旧v4、凛音时序、3D预览；已开始的旧组失败不会隐去后续旧组结果。预检或导入失败则安全停止。

批测必须指定持久输出目录，建议放在仓库外；不把玩家档、缓存、原始重放、大量截图或录屏提交。`--sweep chain` 或 `boss_only` 可分开运行。每种模式均20组合×3策略×种子11/23/47＝180条；同一条各遭遇都显式使用所选种子，正常游戏随机开局逻辑不变。

每条JSON含固定摘要字段 `party, strategy, seed, mode, outcome, rounds_by_battle, knockdowns, hp_remaining, mp_remaining, items_used, decisions, terminal_reason, replay_path`，另附每战setup、初始快照、全部玩家/敌人命令、逐事件日志、终局、重放校验、真实Campaign继承/休息/提交审计。`knockdowns`统计玩家倒地事件次数，`items_used`为初始库存减最终库存，败北仍保留战内消耗；安全档则保留战前资源。

100轮仅为批测失控界限：`advance`可能先进入第101轮并结算首槽状态；工具看到实际轮数超限后立即停止，不再提交该轮命令。即使首槽灼烧已经产生真实引擎胜利，也优先标为 `incomplete`、停止连战、不交付该战果或奖励。`rounds_by_battle`保留引擎实际轮数（例如101），不截成100；原始超限轮事件与引擎终局完整保留供重放诊断。全部失败/超时保存；重放不依赖墙钟。自动结果只说明这些确定策略的行为，不能替代真人体验或证明所有合理策略都能通关。

重放/存档仍为schema 1、战斗规则版本`rpg-0.1`。2026-10-01修正日志浮点传输比较：Godot4.6.3对个别随机采样的单次JSON解析会损失4ULP；现仅接受精确原值，或与重演原值经同版本full_precision stringify→parse一次的结果严格相等。已移除通用2ULP范围容差；不允许邻近数值、第二次运输fallback或修改伤害/RNG。内存重放、整数、ID、事件顺序和RNGstate继续严格比较。

## 公开策略（固定权重，不窥探未来）

实现位于 `tools/rpg/strategy_policies.gd`，只枚举基础动作、已解锁固定技能及现有道具，逐项调用引擎只读预览。仅使用当前可见HP/MP、状态/盾、冷却、轮序与公开意图；不读取seed/RNG状态、未来暴击或未来Boss步骤。同分按基础动作→四技能→字典序道具与目标稳定选择，无可用控制时可回退合法普攻。

共同评分：非暴击预览伤害（上限为目标HP＋现有盾），可击倒另加60；MP每点扣0.7、物品每个扣12；复苏加220；HP≤35%按实际治疗×2；施法者MP≤8时回魔加70；其他无效候选不获分。

- `direct_damage`（直接输出）：共同规则，偏好当前输出/集火，低血急救
- `defensive_counter`（防御反制）：治疗阈值65%、实际治疗×2.2；有效打断加240；当前公开伤害超过自身HP35%时，防御按威胁×1.5计分，不可打断锁定威胁另加100；对受威胁缺血队员施盾，按盾量与缺血量较小值×1.3；被公开指向且低于50%HP的队员获掩护加70；净化加45
- `control_burst`（控制爆发）：有效打断加240；仅尚未存在的有效状态加权：标记80、眩晕95、迟缓45、虚弱50、破甲45、破魔50、灼烧42；不通过反复刷新已有铺垫刷分。非防御策略净化加15

这些是可审阅的简单启发式，未搜索最优策略。每次选择保存理由、得分、引擎预览和资源前后；数值未为胜率或目标轮数调整。正常战3–5轮/Boss6–10轮只作诊断，不强制控局。
