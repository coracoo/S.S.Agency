# 3D 资产管线规则

> 记录于 2026-10-01。来源是已删除的回廊 3D 工具链（`3d_lab/corridor`、`3d_lab/rinne`）。
> 那套代码本身是回廊专用、且无任何外部调用者，已整体移除；这里只留两条踩过并修好的通用规则。
> 新做 3D 资产或写无头验证工具时先读这两条。

## 一、glTF 裁剪后必须校验悬空引用

glTF 2.0 把 `baseColorTexture` / `emissiveTexture` / `normalTexture` / `occlusionTexture` / `metallicRoughnessTexture` 放在 `material.pbrMetallicRoughness` **内部**，不是材质顶层。

只扫材质顶层做「未使用资源」裁剪，会把**全部在用贴图**判成未使用并删除，产出一个表面计数全绿、实际材质全丢的坏文件。计数、包围盒、法线检查全都测不出来。

裁剪后必须回扫，确认每个被引用的 texture / image 索引仍然存在。发现悬空就**中止写文件并报错**——宁可不产出，也不要写出一个能通过所有自动校验但材质已损坏的 GLB。

## 二、无头截图必须由页面自交，不能依赖 Chrome 的截图时机

Chrome 的 `--screenshot` 和 `--dump-dom` 都在 **load 事件**触发。而用 `await` 在模块顶层加载 GLB 的过程**不属于 load 事件**，所以截图拍下的是资产尚未就绪的空场景。

加重试次数、加大 `--virtual-time-budget` 都治不了：虚拟时间会冻结页面，把携带图像数据的 fetch 一起冻住。

正确做法是页面渲染完成后**自己**把画布内容 POST 给本地服务，由服务落盘。配套三点：

- `preserveDrawingBuffer: true`，否则 `toDataURL()` 拿到的是空图
- **失败必须自报**。模块顶层 `await` 的 rejection 不经 `window.onerror`，要显式监听 `unhandledrejection`，并把错误回传给采集端。否则采集端只会报一句无信息量的「超时」，页面自己却在安静地失败。
- **正交相机不接受 `fov`**。`ortho` 是画幅**宽度**（米），高度按实际画布比例推算，不要假定 16:9。给正交相机写 `fov` 不会有任何效果，而 `size` 会停在 1.0 默认值，于是镜头只框住大场景里的一米。

## 验证状态

- 本机装有 Godot **4.6.3.stable**（`J:\godot\Godot_v4.6.3-stable_win64_console.exe`），项目可无头导入与加载。回廊 3D 移除后已实测：`stage_corridor.tscn` 与 `act01_approach_3d.tscn` 均能加载并实例化，`stage_scene.gd` 编译通过、无 3D 桥接残留。
- 但**本次回廊 3D 产出本身的引擎内画面表现，从未验证过**——它已整体删除，该项已无法再验证。上面两条规则描述的是工具链缺陷，不是画面结论。
- 「一个测不出问题的通过项比没有通过项更糟」：包围盒/法线/计数全绿而箱体被压扁、文件大于 2 kB 而图是纯背景色、两次「不同」机位逐字节相同——这些都实际发生过。尺寸下限和计数只能证伪，不能证真，画面必须目检。
