# 参道篇试玩

本次完成第一段可玩的「3D 探索 → 剧情调查 → 独立三人回合战斗 → 原位返场 → 出口完成」闭环。回廊、本殿、自由编队和焰华形态解锁不在本段范围。

## 启动

使用 Godot 4.6.3 打开项目根目录的 `project.godot`，等待资源导入，然后运行默认标题场景，选择 **参道篇试玩**。

- 新开试玩：固定凛音、薄荷、岑照，L5 测试配置，三人分别拥有 HP / MP。
- 继续试玩：恢复最近一次成功保存的参道进度；战中退出会从同一战前状态重新开始。
- 已有试玩进度时，新开需要再次确认覆盖。损坏或未来版本存档不会被静默覆盖。
- 原卡牌剧情入口和原回合制 RPG 试作入口仍保留。

## 操作

- WASD：在真实道路范围内前后左右移动；没有跳跃和自由镜头旋转。
- E：靠近调查点时查看；对白中推进或显示完整当前句。跨对白或弹窗需要先松开按键。
- 1 / 2 或鼠标：选择原有观察分支，两支都汇入后续调查。
- Esc：探索时打开暂停，可以保存、继续或返回标题。
- 战斗：选择基础动作、四个固定技能或道具，点击合法目标，再确认行动。演出过程中不接受重复命令。

读完调查记录不会自动开战。记录成功保存后，再选择「应对异常」并确认。胜利保存成功后，点击继续，恢复进战前的位置、朝向和镜头；目标改为前往上方出口。

## 保存和恢复

试玩只使用 `user://rpg_v1/approach_3d_01.json`。原 `slot_01.json`、卡牌进度和构筑档不被试玩覆盖。

- 对白和调查标记先写成功，再开放下一步骤。
- 进战前保存唯一战斗 ID、固定种子、位置、队伍资源和库存。
- 胜利一次提交实际 HP / MP、库存、40 XP 与异常解除标记；重复点击不会重复奖励。
- 保存失败保留错误界面和可重试战果，不提前开放出口。
- 败北重试、战中退出后继续，都恢复同一战前条件，不额外治疗或赠药。
- 完成本段后继续仍回到参道，不跳入未制作的下一幕。
- 合法但不可达的落点回到本场景安全锚点；非法世界版本、非有限坐标和错误场景归属被拒绝。

## 本次使用的现有内容

保持原参道对白、两种观察分支、水钵调查说明及 xlsx 编辑源不变。战斗沿用首测的纸妖疾行、纸妖守盾、固定技能、初始道具和 L5 数值。高清人物与场景融合素材沿用已接受版本，不新增或重绘素材。标题凛音、试玩对白的凛音／薄荷上身、战斗三人头像统一从已选高清待机帧显示；只改变 UI 取景，不修改原图像素。旧对白 speaker `hakuyo` 在本试玩显式对应薄荷 `mint`，剧情文本与 xlsx 不变。

## 验证入口

自动测试必须从隔离 runner 运行，不向真实玩家目录写测试存档：

```sh
python3 -m unittest tools.rpg.test_run_checks
python3 tools/rpg/run_checks.py --suite all --import --legacy
python3 tools/characters/validate_assets.py --all
python3 tools/characters/run_checks.py --suite all
```

人工图形验收使用：

```sh
python3 tools/rpg/run_checks.py --suite approach --approach-visual --output-dir /tmp/ssa-approach-acceptance
```

该模式先验证临时 `user://`，再运行自动检查、启动人工操作窗口。F11 切换窗口尺寸，F12 保存截图和实际状态，F10 结束。只在这个验收模式中提供这些记录热键；它不自动行走、翻页或战斗。

## 已知验证边界

完整人工闭环在云 Linux / Godot 4.6.3 / OpenGL Compatibility / llvmpipe 软件渲染环境完成。云桌面使用 Dummy 音频，未验收实际音频输出；未在用户的 Windows / 目标 GPU 上测量性能。

该软件渲染环境中，探索帧间隔中位约 141 ms、战斗约 13 ms；详见验证报告。视频的 30 fps 是编码帧率，不能用于证明游戏实际帧率。短演示明确标为原速剪辑片段。约 18 分 10 秒的完整人工原片是人物修正前的功能闭环记录；新版人物另有 546 秒实机补录，短片已采用新版人物画面。
