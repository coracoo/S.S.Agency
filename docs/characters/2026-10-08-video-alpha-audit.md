## 指标定义及结果

原生图集区域按 `alpha >= 8` 定义可见，`alpha >= 128` 定义实体。边缘候选为可见区内侧两像素带，外加 `8 <= alpha < 248` 的软透明像素。绿色优势为 `G - max(R,B) > 12`；洋红优势为 `min(R,B) - G > 12`。二者都是颜色线索，无法单独区分衣物本色与污染。

孔洞按八邻接填充后封闭透明区统计；小孔定义为每块不超过 64 像素。孤立斑点定义为不属于最大块、每块不超过 8 像素、离最大块至少约 3 像素的可见连通区域。合法发丝、流苏、粒子和武器都可能进入这些统计。

## 最小优化方案与验收计划（尚未执行生产替换）

先做运行导出帧的保守候选，维持画布、offset、脚锚、帧数、时长和原图集完全不变。新候选与证据放独立目录，保留 SHA256 到原图集／region 的对应。以 guard 跳跃、healer 跑步、rinne 跑步作为正例，mint 灰绿头发、controller 绿发／绿衣和双剑细刃作为误伤保护例。

1. **先限制范围，再去边色。** 仅处理软 alpha 的外轮廓窄带，对每点比较邻近实体颜色；用邻近实体的色差限制残留 G 或洋红的修正强度。第一轮保持 alpha 完全不变，只处理候选边缘 RGB，禁止把 `G <= max(R,B)` 应用于整个人物。已去色造成的彩色边需要这一局部颜色比较，不能依赖绿色优势单指标。
2. **单独试验极小孤立点。** 只对低 alpha、面积很小、离主体明确有间距且没有连续轨迹的块提出清理候选。保持所有大块和细长武器；明确豁免可能的粒子／飘带。不同清理强度单独对照，不与去色混在一次变更里。
3. **不自动填所有小孔，不统一腐蚀。** 当前小孔常落在发丝之间。只有在邻帧和内区颜色都证明是皮肤／织物连续面时，才评估极小孔的局部修补。对灰发、薄衣边、枪尖和刀刃的真实透明度不能以降指标为目标删除。
4. **若找回源视频，再做源级重抠。** 先按帧边界采样验证背景是稳定绿幕；黑底／淡入／不稳定背景帧明确隔离或保留为不可自动处理，禁止当绿幕正常帧进入批量 keyer。源 RGB 对齐后才能评估主体保留率和真实 alpha 闪烁。

每个候选先跑本审计基线，比较相同帧、相同原生分辨率的局部颜色线索、alpha 面积、质心、小孔、散点和画布边界；随后在白／深／棋盘背景逐帧及按登记时长循环检查。记录改动像素数和最大色差，确认不修改实体内区、本色头发、武器端点和脚底接触；纯去色试验应证明 alpha 字节逐帧完全相同。

只有候选完成图像对照后再决定图集接入。接入还需已有资源／动作时序验证和实际运行场景目检。本轮没有宣称已修好抠图、完成 Godot 游戏内验收或人工七章全通。

本轮原始候选保存于证据根的 `refinement-v1/` 与 `refinement-v2/`，复现建议使用新目录。每个目录包含独立图集、逐帧原／候选 SHA256 和指标、四列明暗底对照、三帧连续对照以及四套无损 APNG。APNG按登记时长播放；原登记的浮点时长、画布和偏移完整保留在 JSON 中。没有以调短时长掩盖边缘跳变。

v1 只处理 `8 <= alpha <= 96` 的外轮廓约两像素，与附近实体颜色相比，绿色／洋红优势至少超出 32 才修正 G，最大单通道改动 64、混合强度 0.65。极小点清理另行限制为连通块最多 2 像素、最大 alpha 32、距主体至少 4 像素且前后相邻帧均不支持；不满足条件保留。结果 7,227 个 RGB 像素改变、435 个 alpha 像素清零，但这些点几乎都为 alpha=1，**可见散点计数和色边像素计数没有下降**。实际明暗对照也看不到足够改善，因此拒绝接入。

v2 固定全部 alpha 原字节，放开实体轮廓最外两像素的 RGB，使用向内至少 3 像素的最近实体颜色作参考；仍要求颜色优势超过 24 且比参考多 32，仍限单通道最大 64、混合强度 0.65。身体内部 RGB 完全不动。薄荷显式保护可见包围盒上部 35%，包括原有灰绿头发；该区域在两版中均逐字节不变。v2 禁止孤立点清理，以保证所有 alpha 完全相同。

数值完整性验收已通过：v2 共改 14,442 个外边缘 RGB 像素，77 帧的 alpha 全部逐字节相同，内部 RGB 与薄荷保护区域零变化；11 张候选图集在目标 region 以外零像素变化，所有非目标帧零变化。图集尺寸、region、offset、画布、脚锚及帧时长均与原始清单相同。独立回读的候选帧 RGBA hash 无不符。详情见证据根 `refinement-independent-verification.json`。

为避免“仍超过阈值就看不到进步”，v2 增加连续量：在原始边缘掩码上累计 `alpha/255 × max(色优势−12, 0)`。这能记录去色强度，但也包含合法本色，不单独作为美术质量分。

已实际查看 v1、v2 四组原／候选明暗底图。v2 又查看了 `guard/jump_048`、`healer/run_052` 的四倍最近邻热点图，以及 healer `run_051/052/053`、rinne `run_040/041/042` 的连续三帧对照。枪刃、盾纹、发丝形状没有被削掉，薄荷头发原色保持；局部洋红边变弱，但正常尺寸的整体收益较小，guard 的强绿和彩边仍明显，rinne 的浅色散点因 alpha 固定而仍在。

相邻帧的洋红能量平均绝对差从 guard 的 6,737.69 降至 6,168.60，healer 从 1,444.41 降至 1,076.24，rinne 从 1,340.41 降至 1,184.14。没有发现这一代理指标产生新的整体跳变；mint 的绿色最大相邻差略从 762.20 增至 771.04，不能把平均下降表述为每一对帧均改善。这仍不是光流对齐后的闪烁测量，也不等于人工实时动画验收。

**两版都不建议直接替换生产图集。** v2 通过了结构损伤门槛，但未解决最明显的绿边与散点，质量收益未达到此次接入判断；阈值像素数仍无下降。现有导出 RGBA 的深部彩边与本色、压缩纹理混合，进一步扩大修改范围会增加盾纹、枪刃、头发和衣服误伤。保留两版证据及工具，后续应找回源 RGB／源视频或建立精确逐帧保护掩码，再做源级重抠。不能把“候选工具通过测试”写成“人物抠图已修好”。

### 后续来源只读核对

当前公开人物运行数据由 `tools/campaign/sanitize_runtime_metadata.py` 的白名单投影维护，保留角色、逻辑画布、帧图集区域、偏移、时长、脚锚和事件，不承载原始制作参数或源视频逐帧链。`restore_sprite_frames_timing.py` 引用的制作期 `provenance.json` 在当前七个公开形态目录均不存在。岑照运行清单的本地Git历史可追溯到 `0ef46ff` 的恢复提交，不能据恢复状态字符串或帧名推断源视频时间码。

本机已有21个历史视频与四份抽帧/QA清单的盘点结果仍保留，但没有新的证据将它们对应到七形态正式动作。后续重抠需要源视频或未抠图RGB帧，以及“形态/动作→源文件→选帧位置→运行帧”对应关系；已向用户请求现有素材目录或链接。没有这些资料时，不把历史凛音试片冒认为其他角色的正式源，也不扩大去色范围来掩盖追溯缺口。
