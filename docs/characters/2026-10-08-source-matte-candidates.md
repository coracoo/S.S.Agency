## 1. 先纠正输入来源

LibTV默认下载版和会员原链文件不是同一编码。首次84份下载为106,868,928字节；确认当前会员有效后，经官方CLI显式使用`--vip --without-ai-watermark`补取84份原链，共320,227,563字节。84份SHA256均与节点记录URL中的64位资源名一致，失败0。

例：岑照跳跃默认下载版1,011,269字节，原链2,586,349字节，均为2206×946、24 FPS、121帧、5.041667秒。原链SHA256为`9391030d2b5af8e608622973fbfc9ef50df0a12dede61165664d8efc97313ddd`。重新取得原链排除了下载衍生编码这一变量，但原片内部仍可见彩边，不能把它全归因于下载。

优先输入目录：`build/libtv/source-retrieval-20261008/member-original/`。旧默认下载版本保留作对照。画布与节点范围见[取回记录](2026-10-08-libtv-source-retrieval.md)。

## 2. 当前能确认的问题

- 幕色不同：岑照跳跃、薄荷物品为品红，苏合跑步为蓝，凛音跑步为绿。不能用一个全图去绿参数处理所有视频。
- 第一轮84份下载版的媒体与首帧盘点得到31绿幕、16蓝幕、16品红幕、21其他背景；其中含黑/暗底和过场。该盘点不等于84条原链的完整逐帧美术验收。
- 不少源片里的角色只占几百像素高度。岑照这组对应运行图的缩放约1.364倍，放大使视频已有边缘、压缩痕迹更明显；色键无法找回源片没有的细节。
- 彩边不只在低alpha处：源RGB本身也存在混色，单纯缩紧透明轮廓会损伤发丝、刀尖和衣摆，却未必去掉彩边。
- 早期新候选的FFmpeg遮罩分支发生了自动像素格式转换，灰度运算必须显式锁定灰度，再在混色边界转换；颜色修正的96通道上限也不足以清除近纯幕色的半透明像素。当前候选已修正这两点，未将早期候选登记生产。

## 3. 四组源帧对应

使用整段运行帧顺序比对121帧源片，而不是按单张最像的姿势挑帧。四组最优序列均支持“运行帧数字编号减一＝源视频零基帧号”。循环跑步的单帧可能匹配到别的周期，所以单帧结果不能独立作为导入依据。

| 形态/动作 | 运行选帧数 | 原链节点名 | 统一坐标拟合RMS / 最大误差 |
|---|---:|---|---:|
| 岑照 jump | 25 | guard_jump_firstframe_v004 | 1.032 / 3.117 px |
| 苏合 run | 18 | healer_run_firstframe_v003 | 0.683 / 3.175 px |
| 凛音 run | 16 | rinne_run_firstframe_v003 | 0.545 / 1.482 px |
| 薄荷 item | 18 | mint_item_firstframe_v004 | 0.302 / 1.041 px |

拟合采用整组统一缩放和平移，不逐帧把人物拉到相同包围盒。上述误差是alpha包围盒拟合量，不是姿态/画面质量评分，不证明已经复原制作期全部参数。所有77帧的原帧名、原`duration_ms`与候选源帧位置已保留。

## 4. 实际候选产物

路径：`build/libtv/source-matte-20261008/`，最新四组在`guard-original-v5/`、`healer-original-v5/`、`rinne-original-v5/`、`mint-original-v5/`。

- `matte-candidate.mov`：原链制作的无损透明视频，各121帧、24 FPS、5.041667秒。
- `comparison.mp4`：同一时间轴的原色幕、候选深底、候选浅底三列对照。
- `selected_frames/`：对应77个运行帧的源尺寸RGBA候选。
- `registered/`：77张原逻辑画布尺寸PNG及`candidate.json`；岑照/苏合/薄荷2048×1024，凛音2048×1536，原动作时长保留。
- `receipt.json`：源文件SHA、色幕采样、裁切、滤镜、输出信息及未登记生产标记。
- `review.html`：四组动态与原运行帧静态对照页。

工具为`tools/characters/build_source_matte_video.py`。它按实际幕色做软色键，保留实体内核，仅在轮廓附近修正对应幕色。岑照额外显式启用强互补色修正，未把这个选项默认套用薄荷等角色。坐标回配先在16位预乘alpha下缩放，再还原直通alpha，避免透明RGB参与普通插值造成额外边缘污染。滤镜语义参考[FFmpeg官方说明](https://ffmpeg.org/ffmpeg-filters.html#colorkey)及其premultiply、unpremultiply、maskedmerge章节。

全片使用固定横向裁切范围，不追着人物移动或每帧改画布。四组121帧候选的alpha边界扫描未见接触该裁切边界；这只是裁切线索，不代替武器、发丝和时序目检。已实际查看四组关键帧的明暗底对照，以及原链/默认下载版的岑照同帧对照；没有声称完成游戏内播放验收。

## 5. 本轮判断和后续

**不建议现在直接批量替换生产图集。** 薄荷边缘较利落、灰绿发色得以保留；凛音的浅底散点有所减少，但局部绿色轮廓仍在。苏合细蓝边、岑照衣摆/长戟/鞋附近的深部彩边也尚未彻底解决。候选的优点和剩余问题都放在对照页，不能只凭色优势计数降低宣布完成。

下一步针对残留位置做动作专用的局部颜色/保护掩码，并在相同画布中逐帧复核。其他幕色尤其黑/暗底需单独的前景分割方案，不能套用本色键工具。后续新生成仍遵循用户H3/768P约定；构图应同时兼顾完整武器和有效人物分辨率，不能仅靠过多留白防裁切。

此外，代码阅读发现旧六机关状态直接请求新增机关时，转换函数可能访问不存在的分状态；已增加`states.has(id)`拒绝保护。未运行对应测试，用例已移交其他模型。
