# 七章谜题任务系统设计（仅规划，未实现）

日期：2026-10-08。来源核对基线：`7770411d623e8dc4d5f8efccfd33eb976063fb12`。本文是用户第 6 项要求的规划交付，不代表任务系统、小游戏、任务 UI 或任务存档已经实现，也不授权将这些模块混入当前关卡改造。

## 1. 目标、事实与取舍

用户要求七章具有剧情起伏、地图解谜和策略难度，所有登记为“任务”的内容都必须有解谜小游戏，不能用连续对话、杀敌计数或跑腿交付代替解谜。角色不设人物等级；成长来自装备、道具和技能卡，技能卡可跨职业配置但受武器与容量约束，速度决定战斗行动顺序。谜题解法不检查等级、职业或某张付费卡；任何合法三人队均能使用事件提供的工具。

事实优先级：本次用户要求 → 当前 AGENTS 与批准七章剧情 → 现行实现 → GDD 历史理念。早期 GDD 的世界观、网格/AP、原角色职责和 v4 抽牌规则均不是恢复目标。

研究比较三种方向：独立小游戏合集容易与剧情脱节；清单式收集任务实现简单但不满足用户要求；**推荐把关卡中已建立的规律做成短小游戏，再由任务簿记录玩家的推理与已验证结果**。每章一个主要操作语法，少量组合变化；不做每日任务、经验任务或随机生成委托。

## 2. 任务与地图机关的边界

| 内容 | 当前可先做的关卡模块 | 本文规划、留待后续实现的任务系统 |
|---|---|---|
| 地点 | 原地图实体、道路、遮挡、可逆开关、实地反馈 | 任务地图索引、任务追踪、小游戏入口登记 |
| 动作 | 玩家在场景中旋转、隔断、托住、拆卸、试航等局部操作 | 任务接取、阶段目标、谜题面板、任务生命周期 |
| 状态 | 机关局部状态和已提交世界变化 | 任务发现、线索引用、谜题草稿、提示级别、解答记录 |
| 剧情 | 仍由原事件事务决定对白、战斗、救援与后果 | 读取原事件结果，不能自行写“居民安全”或越章 |
| 奖励 | 已批准战果和独立关卡奖励事务 | 解谜任务领取记录、支线奖励与任务完成展示 |

边界判定：只要新增通用 `quest` 服务、接取/交付 UI、可复用小游戏屏幕、任务完成奖励或任务持久化，就属于第 6 项后续工作。不能把这些改名为“地图交互”后提前实现。现有剧情场次也不批量改名为任务：对白是故事，战斗是遭遇，只有需要观察并操作规则的活动才登记为谜题任务。

地图机关能够独立运行；未来任务只通过稳定的机关操作/提交接口读取结果。任务系统不得复制机关状态机，也不得在后台自动解开一个玩家未操作的机关。旧存档已通过的主线另按第 6 节兼容，不强迫重玩。

## 4. 输入、反馈、失败、重置与帮助

输入一律支持鼠标与键盘：方向键/WASD 选格、确认键拾起/放下、返回键取消当前操作；拖拽有“选中起点—选中终点”的等价操作。手柄按同一焦点图导航。一次按下只提交一次，长按、丢焦点、面板恢复均不能重复动作。

每个操作给三层反馈：选中时显示合法目标和理由；预览显示将改变的连接、受力或声序；提交后显示具体变化，并允许回看本次步骤。正确与否通过文字、形状与方向共同表达，声音和颜色只辅助。证据推理显示“当前足以证明什么”，不提前剧透下一章。

普通谜题无真实时间倒计时。需要表现压力时使用离散步骤计数，详情、暂停、字幕与无操作均不耗步。标准模式步骤用尽只重置当前尝试；可访问模式取消步数限制，保留同一规则与奖励。战斗速度数值只决定战斗顺序，不用于压缩解谜操作时间。

| 失败类型 | 反馈 | 恢复规则 |
|---|---|---|
| 非法目标、工具不匹配 | 指明当前目标缺少哪种作用；不扣任何资源 | 保留草稿，返回当前选中项 |
| 顺序矛盾、接线冲突 | 高亮第一处冲突，并显示其局部结果 | 单步撤销或重置本题；不跳过前置验证 |
| 试验得出否定结果 | 记入“已试、未支持该判断”，说明观察值 | 允许调整假设继续试验，不把合理试验算惩罚 |
| 保护窗口步骤耗尽 | 明确本次漏做步骤 | 恢复本题入口快照与所有任务工具，不重播已读长对白 |
| 离开地图或退出游戏 | 显示尚未提交的布置 | 保存合法草稿；继续时恢复同题同布局，不发奖励 |
| 读取损坏草稿 | 指出任务记录异常，保留原档 | 只能在合法基线之上重置该未提交草稿；不默认主线已完成 |

三级提示按玩家主动请求提供：①复述已收线索；②指出相关对象与范围；③解释关键关系并展示下一步示范。提示不扣银钱、奖励或结局资格。第三层可分步带领操作，但仍提交真实动作；辅助完成记为提示使用，不伪称独立解答。离开再进、加载或失败不把提示级别降回去，也不强制弹出答案。

可访问性验收：声音都有逐字文本/可暂停波形；颜色都有纹样/标签；不存在依赖细微闪光、立体听位或快速连按的唯一线索；支持放大、减少闪烁与镜头移动、取消精细拖拽、完整字幕回看。主线谜题不以真人记忆力或操作速度锁住剧情。

## 5. 任务定义、完成与奖励契约（未来实现规格）

每个任务定义包含：稳定任务 ID、定义版本、章节、来源场次、地点、前置事实、线索来源、工具来源、操作规则、成功验证器、失败/重置策略、三级提示、完成效果白名单、唯一领取键。只登记有限状态和明示规则，不允许任务资源携带任意 GDScript 路径执行奖励。

任务生命周期为“未发现 → 已发现 → 可操作 → 操作中 ⇄ 暂存 → 解答已验证 → 已提交”。重复打开已提交任务只能回看。任务是否满足由命令序列和现行定义重放验证，不信任 UI 单独写入的 `solved=true`。

解谜完成与故事完成分开：机关解答先形成局部成功结果；若所属批准场次尚有战斗、战后对白或居民交接，仍保持“机关已解/事件未结”。只有原场次的全部必要条件完成，原剧情事务才写救援/物证/责任状态。战胜敌人、拥有碎件或商店购买都不能单独把任务标为解开。

任务奖励采用确定性首次领取。主线必需物证进入不可卖、不可丢、不可合成消耗的证据栏；战斗用品与装备进入现有库存。奖励不含经验或人物等级；技能卡奖励仅进入收藏，装备前仍验证武器、容量和合法构筑。取下卡牌不能抹掉已验证的谜题，装备高级武器也不能自动解谜。

## 6. 存档事务、防刷与兼容（未来实现规格）

拟为正式 schema2 增加独立版本化 `puzzle_quests` 扩展，初版 `version=1`。它不塞入 `world.event_flags` 或 `saga.flags`：现行两者须与既有剧情事件精确重放一致。此扩展当前不能直接写入；后续实现必须同时接入根校验器、克隆、序列化、预览纯度、迁移与隔离测试。

扩展记录包括 `definition_version`、当前任务与尝试号、已发现线索引用、工具引用、有限布局状态、合法操作日志、提示级别、验证结果、提交来源、领取键。布局坐标/槽位限定在定义白名单；禁止对象引用、脚本资源或任意路径。线索保留原场次和来源类别，不能只保存“已拥有”。

一次提交的顺序固定为：读持久基线 → 核对修订号和任务/章节/场次归属 → 在候选副本重放合法操作 → 检查所需真实战果和交接事实 → 生成局部完成记录及唯一奖励 → 校验整个候选存档 → 写临时文件并读回校验 → 原子替换 → 更新 UI。任何一步失败都保留原档、工具、银钱和库存；输入锁只在实际持久提交成功后释放到下一阶段。

| 风险 | 必須约束 |
|---|---|
| 刷关键物品 | 领取键为“本周目 ID＋任务 ID＋奖励版本”，每次尝试号不进入领取键；重置、重开、读档、反复互动不能刷新 |
| 重复敌人、召回单位 | 任务不会监听敌方每次倒地发物品；战斗特殊掉落按独立首次胜利账本提交 |
| 提交成功后应用崩溃 | 继续时读取已提交记录；只恢复展示，不再次发奖 |
| 写档失败后重试 | 用相同提交令牌再次验证原基线，成功一次；不得先扣工具再保存 |
| 买卖和解谜并发 | 基线修订不一致即返回重读；不能用旧草稿覆盖新的交易或战果 |
| 旧存档已完成来源场次 | 严格校验旧档后标为 `legacy_satisfied`，只表示沿用旧主线完成事实；不伪造小游戏操作历史，不补发新奖励 |
| 旧存档停在未完成场次 | 迁移到题目安全起点，保留已提交选择/战果/物证；不扣资源、不替用户改选 |
| 未知扩展版本或非法物证 | 明确报错并保留原档，不当空档覆盖，不静默跳过 |

## 7. 防剧情软锁与替代线索

主线最低保证集由事件固定提供：辨认工具、旧物、夹芯工具、修渡木料、遮布、连接图、主线药械、担架、拆线钳和控制实销。商人、随机掉落、某职业或高阶技能卡均不进入该集合的来源条件。可选特殊掉落只增加旁证、可见标记或准备选择，不是唯一真相来源。
