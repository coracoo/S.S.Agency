# 《封灵事务所》代码实施方案（Godot 版）

> 基于 Godot 4.6 + GDScript 现有项目，按 GDD 要求渐进式重构。
> 目标：将当前"通用战棋原型"升级为"港式民俗规则模拟器"。

---

## 一、现状分析

### 1.1 当前代码结构

```
godot-game/
├── scenes/
│   ├── battle.tscn           # 战斗场景（Node2D + Camera2D）
│   └── main.tscn             # 入口场景
├── scripts/
│   ├── core/
│   │   ├── ai_controller.gd      # 简单行为类型寻敌（melee/ranged/tank/mage）
│   │   ├── card.gd                # 卡牌数据类
│   │   ├── card_effect_parser.gd  # 伤害/治疗/移动/护盾/抽牌/能量/状态/吸血/拉人/后撤
│   │   ├── card_resolver.gd       # 目标选择 + 效果执行 + AOE
│   │   ├── deck.gd                # 抽牌堆/弃牌堆
│   │   ├── game_map.gd            # 单层地形（grass/wall/water）+ occupied
│   │   ├── game_state.gd          # 全局状态（players, enemies, map, teamAp）+ 10 个 signal
│   │   ├── hand.gd                # 手牌管理
│   │   ├── json_loader.gd         # JSON 文件加载工具
│   │   ├── pathfinding.gd         # A* + 可达格子计算
│   │   ├── status_effect_manager.gd  # burn/freeze/poison/shield + tick
│   │   ├── turn_manager.gd        # 只有玩家回合逻辑（start/end player turn）
│   │   ├── unit.gd                # HP/AP/移动/护盾/状态/面向
│   │   └── unit_factory.gd        # 从 JSON 创建单位
│   └── scenes/
│       ├── battle_scene.gd        # 主场景（1601行：渲染+输入+高亮+卡牌UI）
│       └── main_scene.gd          # 场景切换
├── data/
│   ├── balance.json               # 抽牌/能量/AP 平衡参数
│   ├── cards.json                 # 卡牌定义（含钟馗专属）
│   ├── enemies.json               # 4 种通用暗影敌人
│   ├── maps.json                  # 1 张兰寺地图（v1 单层格式）
│   ├── statuses.json              # 6 种状态效果
│   └── units.json                 # 4 个玩家角色（凛音/薄荷/焰华/钟馗）
└── docs/
    └── GDD.md                     # 游戏设计文档
```

### 1.2 核心问题

| 问题 | 现状 | 影响 | 解决策略 |
|------|------|------|----------|
| `GameMap` 单层地形 | `terrain: Array` 存 `grass/wall/water` | 无法支持火/水/糯米/墨线叠加 | 重写为多层 + 标签 |
| `TurnManager` 无敌方/环境回合 | 只有 `start_player_turn()` / `end_player_turn()` | 火焰不会蔓延，敌人行动在 `battle_scene.gd` 内硬编码 | 扩展为四阶段回合 |
| `AIController` 行为类型寻敌 | `_get_behavior()` 按 template_id 判断 melee/ranged/tank/mage | 无情绪/恐惧/噪音响应 | 重写为状态机+Utility AI |
| 无 EventBus | `GameState` 用 Godot signal，仅 10 个事件 | 系统间耦合在 `battle_scene.gd` | 新增 EventBus autoload |
| 无 InteractionSystem | — | 无法推/拉/推倒物体 | 新增系统 |
| 无 NoiseSystem | — | 铃铛/推物无战术意义 | 新增系统 |
| 无 SpiritSystem | — | 灵气/封印核心机制缺失 | 新增系统 |
| `Unit` 无恐惧/背包/环境被动 | 只有基础 stats + status_effects | 角色差异化不足 | 扩展数据模型 |
| 地图/敌人数据通用化 | 暗影兵/射手/骑士/术士 | 没有纸人/水鬼/棺材 | 重写数据文件 |
| `battle_scene.gd` 1600+ 行 | 渲染+输入+高亮+卡牌UI 全在一个文件 | 难以维护和扩展 | 拆分职责，Core 逻辑下沉 |

### 1.3 可保留资产

- **卡牌框架**：`Deck/Hand/Card/CardEffectParser/CardResolver` 数据结构和流程完整，扩展效果类型即可
- **状态效果框架**：`StatusEffectManager` 的 tick 机制可复用
- **寻路系统**：`Pathfinding` 的 A* + 可达格子算法可复用，扩展地形消耗查询
- **单位工厂**：`UnitFactory` 的 JSON 创建模式可复用，扩展字段解析
- **渲染基础**：`battle_scene.gd` 的等距渲染和输入处理逻辑可复用
- **JSON 加载**：`JsonLoader` 直接可用

## 二、重构策略

### 2.1 核心原则

1. **数据先行**：先定义 JSON Schema，再写解析代码，最后写逻辑
2. **事件驱动**：新增 EventBus（Autoload），系统间不直接调用，通过事件通信
3. **配置化规则**：交互规则不写死，走 `rules.json` + `TerrainSystem` 解析
4. **渐进式重构**：每 Phase 结束时代码可运行，不追求一次到位
5. **保留渲染层**：Core Layer 重构期间，Rendering Layer 只做最小适配

### 2.2 技术决策

| 决策 | 说明 |
|------|------|
| 标签系统用 `Dictionary` | 每格维护 `tags: Dictionary`（key=tag, value=true），查询 `has()` O(1) |
| 效果层用三维数组 | `effects: Array[Array[Array]]`，`effects[col][row]` 存 `EffectEntry` 数组，支持多效果共存 |
| 物体层用 ID 引用 | `objects[col][row]: String`，实际定义在 `objects.json` |
| 规则表运行时加载 | `rules.json` 启动时解析为规则数组，`TerrainSystem` 遍历匹配 |
| AI 状态机用配置驱动 | `enemies.json` 中定义 `aiProfile`，`AIController` 读取后按条件转换 |
| 噪音传播用 BFS | 曼哈顿距离扩散，每格衰减，穿墙额外衰减 |
| EventBus 用 Autoload | `event_bus.gd` 注册为项目 Autoload，全局可用 |

## 三、实施阶段

### Phase 1：数据层重构 + 地形系统（Week 1-2）

**目标**：建立多层地图 + 标签系统 + 交互规则引擎，火焰可点燃蔓延。

#### 3.1.1 新增数据文件

| 文件 | 说明 |
|------|------|
| `data/terrains.json` | 地形定义（oil/water/wood/rice/seal/stone/curse/elevated），含 tags、move_cost、color |
| `data/objects.json` | 环境物体定义（brazier/water_barrel/rice_bag/bell/door/coffin），含 pushable、tags、interact |

| `data/rules.json` | 交互规则表（fire+flammable→ignite 等），含 trigger/results/conditions |
| `data/ai_profiles.json` | AI 参数配置（paper_doll/red_lady/water_ghost/zombie/coffin_boss） |

#### 3.1.2 重写/扩展数据文件

| 文件 | 改动 |
|------|------|
| `data/maps.json` | **重写为 v2 格式**：支持 `layers.ground/effects/objects/collision`，含初始物体和初始效果布局 |
| `data/units.json` | **扩展**：新增 `fearThreshold`, `spiritSense`, `environmentPassive`, `inventorySlots` |
| `data/enemies.json` | **重写**：纸人/红衣女/水鬼/僵尸/棺材主，含 `aiProfile` 引用 |
| `data/cards.json` | **扩展**：新增环境互动类卡牌（push_strike, ignite, water_splash 等） |

#### 3.1.3 新增核心系统

| 文件 | 改动 |
|------|------|
| `scripts/core/event_bus.gd` | **新增**（Autoload）：<br>1. 继承 Node，注册为 Autoload<br>2. `emit(event_name: String, data: Dictionary)` — 发射事件<br>3. `on(event_name: String, callable: Callable)` — 注册监听<br>4. `off(event_name: String, callable: Callable)` — 取消监听<br>5. 内部用 `Dictionary[String, Array[Callable]]` 存储监听列表 |
| `scripts/core/game_map.gd` | **重写**：<br>1. 内部存储改为 `layers: { ground, effects, objects, collision }`<br>2. 新增 `terrains_data: Dictionary` 存地形定义（从 terrains.json 加载）<br>3. 新增 `objects_data: Dictionary` 存物体定义（从 objects.json 加载）<br>4. `get_tags(col: int, row: int) -> Dictionary` 聚合查询（合并地形+效果+物体标签）<br>5. `has_tag(col: int, row: int, tag: String) -> bool` 快速查询<br>6. `add_effect(col: int, row: int, effect: Dictionary)` 添加效果<br>7. `remove_effect(col: int, row: int, effect_type: String)` 移除效果<br>8. `get_object(col: int, row: int) -> String` 获取物体 ID<br>9. `set_object(col: int, row: int, object_id: String)` 设置物体<br>10. `is_walkable()` 考虑 collision + 物体阻挡 + 标签 |
| `scripts/core/terrain_system.gd` | **新增**：<br>1. 加载 `rules.json`，解析为可执行规则数组<br>2. `check_interactions(pos: Vector2i)` — 检查指定格子所有标签的交互规则<br>3. 监听 EventBus 事件：`fire:ignited`, `object:pushed_over` 等<br>4. 规则匹配：遍历规则表，检查 `trigger.source_tags` 与 `target_tags` 是否匹配<br>5. 执行结果：添加标签、生成效果、造成伤害、触发连锁事件 |
| `scripts/core/interaction_system.gd` | **新增**：<br>1. `push(entity: Unit, direction: Vector2i) -> bool` — 推动物体/单位 1 格<br>2. `pull(entity: Unit, direction: Vector2i) -> bool` — 拉物体，角色后退 1 格<br>3. `push_over(entity: Unit, pos: Vector2i) -> bool` — 推倒容器<br>4. `interact(entity: Unit, pos: Vector2i, action: String)` — 敲铃铛/开门/点火<br>5. `pick_up(entity: Unit, pos: Vector2i) -> bool` — 拾取物品到背包<br>6. `place(entity: Unit, pos: Vector2i, item_id: String) -> bool` — 放置背包物品<br>7. 所有操作通过 EventBus 发射事件，AP 消耗校验 |

#### 3.1.4 GameState 扩展

| 文件 | 改动 |
|------|------|
| `scripts/core/game_state.gd` | **扩展**：<br>1. 新增 `spirit_density: int = 0`<br>2. 新增 `environment_objects: Dictionary` 存活着的物体实例<br>3. 新增 `noise_map: Dictionary` 当前噪音分布<br>4. `_init()` 读取新 maps.json v2 格式<br>5. 保留现有 signal 用于 UI 更新，系统间通信迁移到 EventBus |

## 四、文件修改总清单

### 新增文件（15 个）

```

scripts/core/terrain_system.gd      # 地形交互规则引擎

scripts/core/spirit_system.gd       # 灵气密度管理 + 封印规则

scripts/core/ai_profile_loader.gd   # AI 参数加载

scripts/scenes/tutorial_overlay.gd   # 教学引导 UI
data/terrains.json                  # 地形标签定义
data/objects.json                   # 环境物体定义
data/effects.json                   # 地形效果定义
data/rules.json                     # 交互规则表

## 六、风险规避

| 风险 | 缓解措施 |
|------|----------|
| 范围爆炸（Scope Explosion） | 严格按 Phase 验收，不提前做 Phase 3+ 的内容 |
| 规则失控 | 所有交互必须进 `rules.json`，禁止代码硬编码 |
| 系统耦合 | 新增 EventBus，系统间只通过事件通信，禁止直接调用 |
| 渲染层拖慢重构 | Core Layer 重构期间，Rendering Layer 用占位图形 |
| 地图数据格式反复修改 | v2 格式先在 `maps.json` 注释中写 Schema，经评审后再填充数据 |
| AI 不可预测 | 意图预览必须显示真实计划，不允许"假预览" |
| 性能问题（Tile 查询） | 标签查询用 Dictionary has()，不遍历；传播计算用 BFS 限制最大深度 |
| battle_scene.gd 太大 | 优先拆分环境互动UI为独立 Control 节点，Core 逻辑下沉到各系统 |
| GDScript 无 Set 类型 | 用 Dictionary 模拟（`{tag: true}`），`has()` 查询 O(1) |

## 七、开发检查清单

每完成一个系统，对照以下检查：

- [ ] **数据配置化**：规则/参数是否在外部 JSON 中？
- [ ] **标签化**：是否没有硬编码地形名/敌人类型？
- [ ] **事件化**：系统间是否通过 EventBus 通信？
- [ ] **可测试**：核心逻辑是否可脱离场景独立测试？（RefCounted 类可 new 后直接调用）
- [ ] **可渲染**：battle_scene.gd 是否能正确显示新内容？
- [ ] **可交互**：玩家操作后是否有正确反馈？
