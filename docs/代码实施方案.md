# GDD v4 渐进落地方案

> 更新：2026-09-30。依据 [GDD v4](GDD.md)。本文件给出设计迁移边界与分期，不是已经执行的代码改造。
> 原方案见 [历史归档](archive/2026-09-30-before-v4/docs/代码实施方案.md)。

## 一、改造边界

继续使用 v3 标题、探索、卡牌战和现有素材；不新增一套平行 v4 场景树，不恢复战棋，也不把美术重做列为前置。

当前 `battle_canvas.gd` 同时承担表现、卡牌与回合结算。新增机制前按实际需求抽出可独立验证的逻辑，画面层继续展示相同背景、卡牌和角色。模块命名在实现时确定，不把下表当作现有文件。

| 拟分离职责 | 输入／输出 | 边界 |
|---|---|---|
| 战斗状态与回合结算 | 单位、牌组、场景状态、行动 → 新状态与事件 | 不持有 UI、纹理或屏幕坐标 |
| 卡牌与目标校验 | 卡牌、目标、费用 → 可用性和效果 | 预览与实际结算复用同一规则 |
| 场景规则 | 显式槽位邻接、能力与状态 → 连锁事件 | 无网格寻路，无屏幕距离逻辑 |
| 目标评估 | 战斗／仪式条件、时间点 → 继续／成功／失败及原因 | 失败优先，支持指定回合结束检查 |
| 案件状态与存档 | 临时事实、长期事实、节点、领取记录 → 存档与回流 | 版本化，奖励幂等，重试不污染长期事实 |
| 卡牌收藏与构筑 | 收藏、角色、规则 → 合法牌组 | 与当前遭遇发牌分离 |

跨系统事件按项目习惯使用字符串 EventBus；数据模型不反向调用场景。旧 autoload 与 v2 数据有引用时先检查，不能整目录删除。

## 二、分期与验收

### A：现状核验与最小结算边界

- 记录三幕探索、回廊战、Boss 战的当前行为和资产引用。
- 以现有 5／6 种牌保持行为兼容；新增字段提供旧数据默认值。
- 统一多敌目标、状态与意图；把伤害来源和控制适用性变成可显示信息。
- 验证错误目标不扣费、重复结束回合不重入、死亡单位不行动、连锁顺序确定。
- 查清「火势传播一跳」「波级状态独立化」与当前行为的差异，作为明确规则变更记录。

出口：旧配置能运行，新结算有针对性的逻辑用例；保留画面与操作基本节奏。

### B：深度构筑与有限成长

- 编辑源扩展稳定卡 ID、所属角色、效果、解锁和升级；再扩导出校验。
- 在现有 UI 材质上增加收藏、16 张牌组编辑、预组恢复、器物与主战／支援选择。
- 加入护盾、标记、整理等首批机制，扩充约 24 种牌的原型池。
- 至少实现斩击和控场两条路线，结界先作为共享终结分支。
- 存取构筑和成长，不把新增奖励直接塞进当前牌组。

出口：费用、复制上限和角色限制能校验，两套牌组均可通关；随机手牌与控制循环通过验证。

### C：仪式目标与道具

- 扩展遭遇类型、目标／失败条件、检查时机、案件道具与时间线。
- 将 `_show_clue_closeup` 当前直接跳战斗的流程扩为调查结果路由；可回探索、进对话、普通战或仪式。
- 在现有回廊制作守灯原型，使用现有背景热区，不先做新地图。
- 新道具栏与手牌分离，提示来自调查手记，重试恢复必需道具。

出口：不同合法牌组都能取得必需道具；时限成功、灯灭失败、缺条件失败、重试恢复均有验收。

### D：单元闭环与音乐

- 串联参道 → 回廊 → 本殿 → 余波，接上对话事实、案件状态、持久收藏与奖励。
- 核验 `NarrativeState` 可复用部分，升级存档格式并提供迁移／回退。
- 关键节点自动保存；读档返回正确场景、已读对话与案件节点。
- 为调查、紧张、揭晓和余波接音乐／环境层次，保留现有音效。

出口：完成一次普通通关、失败重试、退出读档、重玩案件；无重复奖励，人工能复述本集故事。

### E：内容扩展

先测定一集的文本、背景、动画、卡面、音乐与验证成本，再排新单元。特别篇、周年和大事件复用案件框架；不预设联网运营或限时系统。

## 三、配置迁移原则

1. 以 `config/dialogue.xlsx`、`battle_config.xlsx`、`stage_config.xlsx` 为现有编辑源，先加校验再接运行时。
2. 新的案件／收藏／构筑表先定义唯一编辑入口；不得长期维持 xlsx 与手写 JSON 两份可独立修改的真源。
3. 保留已有 ID 与资产路径；新增卡的升级分支不能绕过基础卡重复上限。
4. 先验证旧配置兼容，再迁移样章；规则变化要同步卡牌文字、意图预览和测试。
5. `project.godot`、默认入口、素材、导出包只有在对应实施任务中才变更。

## 四、验证范围

逻辑层测试仅覆盖真实风险：目标／费用一致性、状态时限、连锁、条件优先级、随机循环、公平道具、存档迁移和幂等奖励。表现层沿用 Godot 导入、场景冒烟与实际截图检查；不能把无头测试当作画面验收。

构筑平衡需固定随机种子对照和真实随机试玩；自动连招只作基础冒烟。叙事需人工体验，检查战斗长度、提示质量和余波。

## 五、本次没有执行的事项

本次未改游戏代码、配置、素材或运行包；未宣称新机制可玩，未执行批量素材生成。当前交付是备份、GDD 与配套文档的统一。
