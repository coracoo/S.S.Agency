# 《逢魔退治帖》游戏设计文档 v4.0

> 修订日期：2026-09-30。最近一周核对窗口：2026-09-24—2026-09-30。
> 用户确认方向：**深度卡牌 RPG＋单元故事**；日式水彩绘本、伪 2.5D 横屏、现有素材和玩法基础保持。
> 本文是新版设计基准，**不是功能完成报告**。「保留」表示现有基础；「新增设计」需要后续实现；原型数值均待试玩验证。
> 代码基线：`5078510`（2026-09-29）。旧稿见 [v3 GDD 原文](archive/2026-09-30-before-v4/docs/GDD.md)，实际接线见 [进度与现状](进度.md)。

## 一、定位与边界

**一句话描述**：玩家经营自己的退魔牌组，在逢魔町调查一件件志怪委托，通过卡牌战斗与回合仪式介入人物命运，逐步发现整个世界的秘密。

日式 RPG 是视觉、场景和演出语言；道家志怪、符箓、阴阳术与人鬼关系是世界观创作资源。保持《逢魔退治帖》名称、逢魔町、退魔寮、现有人物和神社场景，不启动题材换皮或美术替换。游戏术法按虚构世界规则自洽，不将创作设定当作现实宗教史结论。

| 支柱 | 玩家体验 | 设计取舍 |
|---|---|---|
| 深度卡牌 RPG | 围绕角色、卡牌和器物形成自己的打法 | 深度来自构筑、费用、留牌、克制和场景取舍；主线提供预组牌 |
| 单元故事 | 每个案件有完整情绪收尾，人物与秘密跨案件积累 | 先确立人物处境，再决定战斗和谜题 |
| 回合仪式解谜 | 从证词、画面和声音理解规律，以道具改变现场 | 必需道具保证获得，压力来自时机与行动分配 |
| 视听叙事 | 背景、半身立绘、音乐共同表达真相与情绪 | 保留水彩绘本和现有 2.5D 演出，完善关键镜头 |

首个产品范围为本地单人章节 RPG。长期通过新案件、篇章、特别篇、周年故事与大事件扩展。联网服务、抽卡商业化、每日任务和实时运营系统不属于本轮要求。

## 二、保留基线与修订决策

### 2.1 保留

- 1920×1080 横屏、完整水彩背景、和纸纹理、朱砂与金缮 UI、现有字体和素材。
- 探索中的行走、台阶贴脚、透视缩放、前景视差、中景遮挡、线索特写。
- 委托挂轴、半身立绘对话、逐字显示、分支选项、卡牌详情与扇形手牌。
- 战斗角色动画、多敌人表现、目标选择、费用、抽牌堆／弃牌堆、留牌补满。
- 居合斩、引燃、鸣钟、倾覆、结界符；场景槽、火势连锁、灵气压力、破阵、封印、执念。
- `config/*.xlsx → 校验导出 → JSON → Godot` 配置方式和现有本地后台。

### 2.2 撤销的旧要求

| 旧要求 | 新基准 |
|---|---|
| 横版化后整体保留战棋规则和 AI | 战斗使用单位目标、场景目标和意图，不使用网格移动、射程、背刺或寻路 |
| 所有谜题零文字、纯画面 | 文本、画面、声音共同提供线索，允许手记与分级提示 |
| 全部敌人沿用巡逻／搜索／追击状态机 | 战斗以可预测意图、阶段和单位状态驱动 |
| 推距、无声步等被动与数值原封不动 | 保留人物，按卡牌职责重新设计被动 |
| 所有战斗依赖环境封印收尾 | 普通战可直接取胜；封印是部分关卡和构筑的有效路线 |
| 所有案件固定侦查 1—3、惊醒 4—6、决战 7+ | 案件和遭遇分别配置阶段，按剧情需要设置 |
| 继续替换整套画风、重做现有素材 | 以当前成品为基准复用，仅补具体内容缺口 |

探索落脚线、遮挡深度属于表现和导航；场景槽邻接属于连锁规则。两者都不构成战斗棋盘。

## 三、游戏循环与单元结构

1. **一回合**：读意图和场景 → 分配灵墨 → 出牌／用道具 → 场景与敌方结算 → 调整计划。
2. **一个案件**：承接委托 → 调查对话 → 获得线索、试用牌或案件道具 → 战斗／仪式 → 揭晓真相 → 处理与余波 → 成长。
3. **一个篇章**：独立案件 → 人物关系与组织线索积累 → 跨案件事件 → 篇章收束并开放下一片世界。

案件不要求同一流程：可有无 Boss 的案件，也可有多场战斗与仪式组合。不得把每个调查点默认转换成战斗。

原型目标为 20—30 分钟的完整样章，复用参道、回廊、本殿，包含普通战、仪式和 Boss 战。正式单元可扩大到约 45—90 分钟；时长是内容预算，试玩后调整。

每集包含一个人物困境、一条可理解的异常规律、一条本集闭合的事件线、至多一条主要长期伏笔。每个新单元引入一个主机制，用旧规则组合变化。结案后保留日常或余波，奖励面板不能挤掉情绪收尾。

## 四、世界观与角色

逢魔町的黄昏是人间与异界交错的时段。退魔寮调查异常的来由，再决定退治、镇压、安抚、修复或放行。纸人形、残响、棺守和神社三幕继续作为第一批内容资产。

符建立约束，铃影响灵体，镜帮助辨认，水火改变现场，旧物连接记忆。具体用途由案件建立，不假设玩家懂民俗术语。

以下为**新增角色设计**，保留现有人物与视觉：

| 角色 | 卡牌职责 | 主要取舍 |
|---|---|---|
| 凛音 | 稳定斩击、防护、破阵 | 保住生命与迅速压低敌人 HP |
| 薄荷 | 调整手牌、标记、器物利用 | 为下一回合准备与立即输出 |
| 焰华 | 引燃、净火、场景增益 | 借火压制与损坏阵眼／触发执念的风险 |
| 清明 | 结界、防护、灵气调节 | 承受准备期压力与争取封印窗口 |

角色实装程度不同；此表不宣称四人均能在 v3 正式出战。

首期组队设计采用**一名主战＋一名支援**：主战承受伤害并提供基础生命和主体卡池；支援提供卡池与一项被动，以立绘和施术演出参与，不另设生命或站位。战前选择，战中不换主战。多人独立生命队伍不作为首期前置。

## 五、深度卡牌系统

### 5.1 深度来源

- 战前选择主战、支援、卡组和器物，确定费用曲线与取胜路线。
- 战中出牌消耗灵墨；留牌占用补牌空间；整理手牌也付出成本。
- 攻击敌人、改变背景、保护目标争用资源。
- 火势与灵气同时提供机会和压力；控制与封印有可查的适用条件。
- 长期成长扩大可用工具，不靠无限等级与叠乘倍率维持内容。

第一战先教攻击与防护，再教场景控制，随后开放构筑与封印。术语可从卡牌详情直接查看。

### 5.2 牌组规则（新增设计）

| 项目 | 首期原型规格 |
|---|---|
| 正式牌组 | 固定 16 张；至少 6 张来自主战，支援卡最多 6 张，其余为主战或通用卡 |
| 示例 | 主战 8 张＋支援 4 张＋通用 4 张，不是强制比例 |
| 重复上限 | 同一基础卡最多 2 张；升级分支合计占同一上限；独特卡最多 1 张 |
| 新卡 | 进入收藏，不自动加入牌组；战前或案件安全节点编辑 |
| 入门保障 | 合法预组、一键恢复预组、牌组保存、费用分布提示 |
| 首批牌池 | 约 24 种战斗卡，覆盖至少两套可通关构筑；不同时铺开四人完整卡池 |
| 必需道具 | 不计入 16 张，不进入随机抽牌堆 |

现有 Demo 的 10／12 张预设牌组继续作为基线。16 张是构筑原型目标，不能在卡池与 UI 尚未补齐时直接替换旧配置。

### 5.3 灵墨、留牌与循环

保留现有基础：每回合灵墨恢复至上限，默认原型为 6；手牌上限 5；未用牌保留；新回合补至上限；普通牌打出后进入弃牌堆；抽牌堆耗尽时重洗弃牌堆。

- **灵墨**是出牌资源，沿用代码 `ap` 命名；**灵气**是场景压力，界面区分两者。
- 未用灵墨默认不跨回合积累。费用以 1—3 为主，昂贵终结牌单独论证。
- 新增「消耗」语义：该牌进入本场移除区，下场恢复，不永久删除收藏。
- 新增「整理」：每回合一次，花 1 灵墨选择一张手牌，将其暂存以腾出一个手牌位，再从其他可抽牌中抽一张，最后把暂存牌弃置；没有其他可抽牌则不可用、不扣费，不能抽回刚选中的牌。
- 抽牌不能超过手牌上限；超出的数量不继续抽取，卡牌详情预告实际抽取量。
- 回费、抽牌和控制组合必须验证上限，禁止无限循环和永久跳过敌方所有行动。

### 5.4 类型与标签

| 类型 | 目标 | 职责 |
|---|---|---|
| 攻击 | 敌方单位 | 伤害、标记利用、破除护体 |
| 防护 | 主战或明确的保护目标 | 护盾、减伤、净化 |
| 术法／辅助 | 单位、手牌或场景指标 | 理牌、控制、调节灵气 |
| 场景 | 背景合法器物 | 引燃、鸣钟、倾覆与连锁 |
| 结界 | 明确标出的阵眼 | 准备和触发封印 |

类型与标签分开：一张牌可带火、符、器物等标签；标签本身不暗示未写明的伤害或控制。任何组合效果都须写明条件、目标和消耗。

### 5.5 构筑方向

| 方向 | 核心循环 | 优势 | 弱点 |
|---|---|---|---|
| 斩击破阵 | 标记／防护 → 进攻 → 破护体 → 输出或封印 | 较少依赖场景 | 准备过多会拖慢击杀，需承担伤害 |
| 火势控场 | 引燃 → 借势进攻 → 鸣钟／倾覆清场 → 重建窗口 | 改变场景、压低部分威胁 | 执念反制，火势妨碍布符 |
| 结界镇压 | 防护／理牌 → 调节灵气 → 布符 → 镇压 | 准备换取高价值终结 | 准备期受压，Boss 仍需破护体 |

首版验证前两种，镇压先作为共享终结分支。普通遭遇至少支持两条有效路线，避免普遍要求唯一配方。

### 5.6 起步卡牌示例

现有卡继续按当前数据运行。新数值仅用于试算，名称可调整；牌面描述必须与实际结算一致。

| 卡牌 | 费用 | 规则或方向 | 状态 |
|---|---|---|---|
| 居合斩 | 2 | 保留基础伤害 8 的校准点，场景增益在预览显示 | 现有 |
| 引燃 | 1 | 令合法场景槽燃烧，保留连锁与恐惧关联 | 现有 |
| 鸣钟 | 1 | 保留惊焰与控制特色，显示适用对象和免疫 | 现有 |
| 倾覆 | 1 | 保留相邻火势扑灭 | 现有 Boss 牌组 |
| 结界符 | 2 | 对阵眼布符，按本场规则判定封印 | 现有 |
| 守势 | 1 | 获得 4 护盾 | 新增原型 |
| 护身符 | 2 | 获得 7 护盾，解除一个可净化负面状态 | 新增原型 |
| 识破 | 1 | 对一敌附加 1 层标记 | 新增原型 |
| 追符斩 | 2 | 造成 6 伤害；消耗目标 1 层标记时额外造成 5 伤害 | 新增原型 |
| 净息 | 1 | 灵气降低 2，可能避开高压，也可能推迟封印 | 新增原型 |

新增原型中：护盾先于生命承伤，剩余护盾在下次玩家回合开始清空；标记最多 3 层，仅被明确消费它的牌消耗，留存至波次结束。护盾和标记不属于当前运行时完成承诺。

## 六、常规战斗与敌人

### 6.1 对象和意图

保留背景中的角色动画；冲刺、挥刀、击退是演出，不改变距离或命中。操作通过单位高亮和场景热区选择目标。

当前多敌人各有 HP，但一波共享意图及部分状态，这是原型限制。新增设计要求每个敌人独立记录护盾、标记、控制和意图，显示目标、效果和预计伤害。群体技能可共享演出，单体控制不能暗中作用全体。

纸人形继续承担火势教学，残响突出控制抗性，棺守突出破阵、执念和封印窗口；保留其文化形象与立绘。

### 6.2 回合结算契约（新规则实现时遵循）

1. 回合开始：清除到期护盾／状态 → 按配置变化灵气 → 灵压及失败检查 → 恢复灵墨 → 补牌 → 公示意图。
2. 玩家行动：校验费用和目标 → 原子结算卡牌与直接连锁 → 更新预览 → 检查死亡和即时目标。
3. 结束回合：火势传播 → 倾覆灭火 → 仪式进度与封印检查 → 敌方按预告顺序行动 → 状态时限与回合目标结算。
4. 每一步后检查失败；成功须同时满足保护目标存活等必要条件。成功、失败同时成立时失败优先；已达成有效成功时不追加剩余敌方攻击。
5. 进入下一波或下一回合；同一输入只推进一次，演出期间禁止重复提交。

火势应基于开始传播时的燃烧槽快照扩散一跳，避免遍历顺序决定一回合烧几层。这是拟修正规则，不宣称当前已符合。

### 6.3 胜负与封印

- 普通战消灭本场全部波次，或满足开战前写明的替代目标。
- 护送、打断、破阵等附加条件必须提前说明。
- 封印保留「阵眼＋灵气＋Boss 护体条件」；阵眼数量来自本场配置，不统一写死为 3。
- 默认封印当前波符合条件的敌人，不清掉未登场波次，不直接完成整个案件。
- 无封印条件的遭遇不能强制携带结界牌；战前允许换掉无效牌。
- 控制免疫／抗性提前可查，不能临时改规则；强控不能无限锁住所有敌人。
- 失败可快速重试并进入战前构筑，不强制重播已读长对话。

## 七、场景连锁与灵气

保留纸门、铃、水钵、阵眼及燃烧、鸣响、倾覆、封印表现。连锁按场景槽 ID 和显式邻接执行，不按屏幕距离猜测。

选中场景卡时高亮合法目标，展示结果和执念风险；非法目标不扣费。未来按能力字段收紧目标资格前，须补齐旧场景的可用对象，不得使现有牌全部失效。

普通战建议聚焦 0—3 个主要对象，仪式 3—5 个。这是阅读负担预算，不是删除当前槽位的命令。每场优先表现一个核心矛盾，例如火能压制纸人，也妨碍布符。

灵气继续为 0—10，保留按遭遇配置的倍率和压力。升高可以开放镇压，也增强威胁；普通战可关闭增长，仪式可将其作为失控压力，不要求每场显示灵气条。

当前 6 阈值封印、8 阈值高压等属于具体 Demo 配置。正式内容由关卡决定，UI 显示本场阈值、下一次变化和原因。统一预览与实际伤害，列出基础、场景、状态、灵气、执念来源，同一来源只乘一次。

## 八、回合仪式与案件道具

### 8.1 独立目标，共享交互

仪式复用背景、卡牌、特效和回合 UI；胜负由目标条件判断，不伪装成高血量敌人。类型包括守夜、辨认、修复、护送和限时阻止。

「坚持 N 回合」提供压力；玩家还须根据线索在正确对象和时机完成操作，不能连续空过回合解决主要谜题。

### 8.2 道具保障

- 战斗卡属于长期收藏和随机手牌；案件道具属于本集剧情状态。
- 必需道具固定取得，进入独立栏位，不占手牌和牌组容量。
- 道具可消耗灵墨或次数；费用、前提和目标使用前可查。
- 关键消耗品须可补充、安全试用，或重试恢复；误用一次不能永久卡死主线。
- 可选调查提供提示、容错或替代路线；不起眼的漏点不能让玩家失去必胜道具。
- 仪式提供基础防护／维持手段，保证最低合法构筑可完成；好牌组提高容错与效率。

### 8.3 原型：《回廊守灯》（新增，复用现有画面）

棺守仍在等待被遗忘的送行仪式。玩家从参道证词和回廊残文得知「先辨认、再安放、最后引路」，随后决定如何处理它。

复用回廊、吊钟、水钵和纸门，先用现有热区与文字承载状态，不把新场景图作为前置。

| 阶段 | 信息／变化 | 玩家目标 |
|---|---|---|
| 调查 | 证词说明第三次叩门，残文说明送行顺序 | 固定获得辨影镜、灯油、旧物，记入手记 |
| 第 1—2 回合 | 阴风降低引灯稳定度 | 防护现场，用灯油或内置添灯行动维持 |
| 第 3—4 回合 | 第三次叩门后可辨认倒影，窗口持续开放 | 辨认来者，再安放旧物 |
| 第 5—6 回合 | 亡者显现，怨念加剧 | 完成引路，守住末次环境冲击 |
| 第 6 回合结算结束 | 判断全部条件 | 存活、灯未灭、辨认完成、旧物安放、引路完成 |

原型试算：稳定度上限 6、初始 4，每回合结束降低 1；内置添灯每回合一次，花 2 灵墨恢复 2；灯油一份，花 1 灵墨恢复 3；辨认、安放、引路各花 1 灵墨，满足前提后可同回合顺序使用。此数值只验证流程可达，不代表谜题已平衡。

灯灭或主战倒下即失败；第 6 回合结束条件不全则失败并指出缺项。对话、暂停、详情不推进回合。辨认不依赖抽牌，失败从仪式入口重试。

### 8.4 提示

手记提供「回顾已发现线索 → 指向相关对象 → 解释关键关系」三级帮助，由玩家主动打开，不扣主线奖励。部分仪式可有多解，每种解法需有可理解反馈和结案支持。

## 九、RPG 成长与数值边界

### 9.1 成长（新增设计）

- 首通解锁卡牌、器物或支援；卡牌进入收藏。
- 卡牌熟练度开放两个互斥升级分支，如稳定增益与条件强化；安全节点可免费切换已解锁分支。
- 主战配置 1 件器物，改变打法并明确触发上限，不叠多套装备词条。
- 篇章里程碑开放卡池和关系事件；基础生命提升设章节上限，不做无限等级压制。
- 重玩提供挑战评价、不同对白与有限额外奖励；主线不强制刷同案获取必需道具。

### 9.2 平衡标尺

以当前「2 灵墨、8 基础伤害」校准新卡，综合条件、目标数、持续时间和控制收益计价。护盾／控制按防止的总伤害比较，不能只比较单张输出。

记录有效伤害、承伤、费用利用率、死牌率、牌组周转、控制覆盖、组合到达时间、总回合数和失败原因。原型节奏目标：普通战 4—6 回合，Boss 7—10 回合，仪式 4—8 回合，均以完整遭遇而非单波计算，避免多波拖断剧情。

至少用攻击构筑、控场构筑、默认预组验证。随机性影响战术，不决定必需谜题道具是否出现。普通敌人不能全部免疫同一流派，关键反制须有可获得的替代方式。以上没有真人试玩结论，禁止写成已验证平衡。

### 9.3 难度（新增设计）

剧情／标准／挑战共享主线。剧情难度降低战斗压力并提供预组与仪式容错；挑战增加组合和资源约束，不独占重要世界观。现有星级结算保留，剧情解锁不绑定高星。

## 十、单元剧情与长期内容

每案制作表包含：委托起因、人物愿望、异常规律、证词矛盾、调查顺序、战斗理由、仪式规则、真相、处理方式、余波、伏笔及回收位置。

选择基于已知信息；小选择影响对白或便利，大选择影响关系和案件结尾。分支在可控节点汇流，避免复制整套后续关卡。持久记录具体事实，如谁知道了什么、承诺是否兑现、某对象是否保留。

| 层级 | 功能 | 扩展方式 |
|---|---|---|
| 单元案件 | 本集情绪与谜团闭合 | 复用框架，增加人物和一条异常规律 |
| 篇章主线 | 积累组织、历史与区域关系 | 案件事实在篇章尾互相印证 |
| 特别篇／周年 | 老人物回归、日常与纪念 | 独立入口、前情补足，结束后进入常驻档案 |
| 大事件 | 改变区域或关系、回收伏笔 | 先有铺垫，再让跨案件人物和机制相遇 |

周年是内容形式，不承诺现有日历运营或限时服务器。关键剧情和功能卡有常驻获取路径，不因错过活动造成后续不可理解或无法构筑。

## 十一、画面、音乐与 UI

以 [风格基准图](reference/style_ref_storybook_rpg.png)、三幕实装和 [美术规范](Art_Bible.md) 为准。保留和纸水彩、暖赭黛青、金缮朱砂及现有角色；不恢复蒸汽朋克，不改为网格战场或全 3D。

人物尺寸、透视和落脚线以近期实装配置为准，撤销旧稿所有人物占屏 40%—45% 的硬指标。镜头不能遮住卡牌、目标和重要提示。

每集规划调查、紧张、揭晓、余波的音乐关系，可用同一主题不同配器。先做好关键转折和静默，再增加曲目。BGM／环境／音效／语音按独立通道规划；现有音效复用，完整音乐叙事仍属新增制作。

保留半身对话与说话者强调，拟增加对话日志、已读快进、自动播放速度和线索回看。声音线索配字幕或视觉提示；演出加速、减弱闪光和震屏列入验收。

战斗保留扇形手牌、卡面、详情，补充构筑界面、标签解释、抽弃牌浏览、伤害预览、免疫原因、结算摘要。探索低干扰，战斗提供充分决策信息，不为留白隐藏规则。仪式显示当前回合／限时、保护指标和已完成条件，道具栏独立于手牌。

### 12.2 拟新增数据职责

以下是设计字段，不是导出器已支持的 schema，实施时扩展现有配置管线。

| 数据 | 最小职责 |
|---|---|
| 卡牌／收藏 | 稳定 ID、角色、类型标签、费用、目标、效果、升级分支、解锁 |
| 玩家牌组 | 主战／支援、16 张卡、器物、合法性与版本 |
| 案件 | ID、前置、节点、遭遇、线索、道具、结案与回流 |
| 遭遇 | battle／ritual、波次或时间线、目标／失败条件、检查时机、奖励 |
| 案件道具 | 获取节点、目标、费用、次数、前提、效果、补充或重试 |
| 持久化 | 案件节点、选择事实、线索、收藏、构筑、成长、领取记录、版本 |

校验 ID 引用、条件可达、必需道具来源。临时状态按案件 ID 隔离，避免重玩污染主线。奖励幂等；重试恢复入口快照与关键道具，不重复发成长奖励。存档升级需备份、版本迁移和失败回退。

现有 `NarrativeState` 可作复用起点，但 v3 的案件／奖励／存档全链路仍需接线验证，不因 autoload 存在就认定已经完成。

## 十三、首个完整样章与验收

样章继续使用「夜巡·逢魔神社」和参道 → 回廊 → 本殿，不替换场景资产。

1. 参道：委托与调查，提供预组，普通战教攻击／防护与一处场景互动。
2. 回廊：固定获得案件道具，守灯仪式让调查所得决定操作顺序。
3. 本殿：整合棺守护体、执念、灵气和封印，战前允许调整构筑。
4. 余波：说明棺守与仪式的关系，处理结果、成长奖励和一条后续线索。

| 维度 | 验收问题 |
|---|---|
| 构筑 | 两套不同合法牌组都能通关，失败原因可解释吗？ |
| 回合 | 留牌、出牌、整理有取舍，还是唯一固定点击顺序？ |
| 仪式 | 必需道具保证取得，流程在最低基础资源下可完成吗？ |
| 剧情 | 能说清来者、原因以及自己的操作改变了什么吗？ |
| 视听 | 线索清楚，关键转折有画面或音乐回应吗？ |
| 接线 | 结案回流、保存／读取／重试是否避免丢失或重复奖励？ |
| 兼容 | 旧配置下三幕与两场战斗仍可运行，素材和画风保持吗？ |

自动演出只能验证流程可达，不能证明构筑平衡、随机公平或剧情体验；最终需要人工体验与多牌组回归。
