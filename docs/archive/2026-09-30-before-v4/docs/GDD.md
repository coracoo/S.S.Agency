## 一、游戏定位

**日式 2D 横屏 RPG：画面驱动的解密 × 环境规则战斗 × 卡牌。**

核心体验：玩家在一幅幅"会说话的绘卷"中穿行——**所有解密线索都画在画面上**（倒影、影子、光线、结界纹路），
战斗不靠数值碾压，而靠读懂环境规则后引发的连锁反应（火、水、铃声、结界），卡牌是触发连锁的"手"。

**一句话描述**：在逢魔时刻的日本小镇上，以画面线索解谜、以环境连锁退治妖怪的 2D 横屏 RPG。

**参考作品**：幽灵诡计（画面叙事解密）+ 奥日/歧路旅人（2D 画质标杆）+ 杀戮尖塔（卡牌手感）+  INTO THE BREACH（可预测敌人意图）

**视觉基准（风格与尺寸的唯一样板）**：`docs/reference/style_ref_storybook_rpg.png` ——
**手绘水彩绘本风 2D 横版**：整幅场景是一幅完整的水彩画（纸质肌理、暖赭色调、柔光、无硬描边），
角色为**大比例人物、占画面高度约 40–45%**（绝非传统地下城式小人头/小精灵），
HUD 极简（仅角落小字）。一切美术与 UI 取舍以这张图为准。

**三大支柱**：

| 支柱 | 说明 | 体验目标 |
|------|------|----------|
| **画面驱动解密** | 谜题信息 100% 由画面呈现，不靠文字提示 | "我看见了，所以我知道了" |
| **活的背景画战斗** | 战斗无战场小人：一幅战斗背景画 + 卡牌对战 UI；卡牌打在背景画的物体上（引燃纸门、摇响吊钟、推落石灯）引发连锁 | "我没动手，是画里的场景杀了它" |
| **卡牌手感** | 抽牌、留牌、打出的动画与反馈达到卡牌游戏水准 | "每张牌都想摸" |

**双模式结构（重要）**：

- **探索模式** = 横版卷轴场景画（§三），角色大比例在画中行走，承担解密与剧情
- **战斗模式** = **背景画 + 卡牌对战 UI**：画面是一幅该遭遇的战斗绘卷（无战场、无走位小人），
  敌人以绘卷立绘呈现于画面深处，玩家以左侧立绘 + 计量条呈现，战斗全部通过手牌进行；
  背景画中预置可交互的**场景槽**（灯笼/纸门/水钵…），是环境连锁的载体

## 二、核心循环

```
进入场景（横版探索，角色行走于画中） → 观察画面线索（光影/倒影/纹路）→ 解开机关推进
        ↓
遭遇妖怪（画面动作触发：踏碎御札、惊动风铃）→ 镜头收拢成画框，切入战斗绘卷
        ↓
读取敌方意图（敌人立绘旁心意气泡）→ 出牌/触发场景槽连锁 → 欣赏连锁演出（慢镜+震屏）
        ↓
退治成功 → 获得卡牌/绘卷残页 → 回到探索 → 下一幕
```

**关键原则**：探索与战斗是两种画面形态但同一套材质语言——探索是"走进画里"，
战斗是"画变成擂台"：战斗背景画与探索场景同风格同场景（战斗绘卷就是当前幕的场景画
视角收拢版），切换靠墨线收拢/拉门转场，无加载黑屏、无模式割裂感。

## 三、横屏舞台：空间模型与镜头语言

### 3.1 空间模型（逻辑层保持网格，渲染层完全侧视）

为最大化复用 v2 规则引擎，**逻辑层仍使用网格**，但网格语义从"等距平面"改为"横版舞台"。
**注意：空间模型只服务于探索模式**；战斗模式不渲染战场，位置与距离抽象为
"敌我立绘位 + 前后排 + 场景槽"（见 §5.2b）。

```
┌────────────────────────────────────────────────────────────┐
│  纵深线 B（后景 lane）：背景平台、檐上、回廊 —— 少数机关可换线   │
│ ══════════════════════════════════════════════════════════ │
│  高度层 3：屋檐 / 横梁 / 鸟居顶        ← 推落 → 坠落伤害      │
│  ────────────────────────────────────────────────────────  │
│  高度层 2：台阶 / 供桌 / 石灯笼顶                             │
│  ────────────────────────────────────────────────────────  │
│  高度层 1：地面主行（角色/敌人的主战场，像素级移动+格点吸附）    │
│  ────────────────────────────────────────────────────────  │
│  高度层 0：水面 / 洼地 / 地下河道（水鬼领域、导电层）           │
│ ══════════════════════════════════════════════════════════ │
│  纵深线 A（前景 lane）：篱笆、土坡后 —— 潜行位、遮挡视线         │
└────────────────────────────────────────────────────────────┘
        ← 横向卷轴（X 轴无限延展，场景按"幕"分隔）→
```

- **X 轴**：像素级自由移动（手感），底层按 64px 列吸附（规则判定）
- **Y 轴（高度层）**：0–3 共 4 层，层间移动靠台阶/跳跃点/被推拉，**从高层推落 = 坠落伤害**
- **纵深线**：A/B 两线，换线点由关卡定义（回廊口、篱笆缺口）；换线 = 1 AP，潜行与遮挡视线的来源
- 原来的"格子效果层/物体层"原样保留：一格 = 64×64 舞台区域，可叠火/水/糯米/结界

### 3.2 镜头语言（画质重点之一）

| 场景 | 镜头行为 |
|------|----------|
| 探索 | 横向跟随（前视差 5 层），角色位于画面 1/3 处，跑动时镜头略领先 |
| 发现机关 | 镜头轻推近（1.2×）+ 环境音聚焦，给出发觉反馈但**不打断操作** |
| 解密特写 | 镜头推满至线索局部（2.5×），进入"绘卷模式"，四周墨色渐晕 |
| 战斗触发 | 探索画面定格 0.2s → 墨线从四角收拢成画框 → 切入**战斗绘卷**（该幕场景画的视角收拢版），敌人立绘自画深处浮现，战斗 UI 浮现（全程 <0.6s，无黑屏） |
| 连锁反应 | 连锁 ≥3 段时插入 0.3s 慢镜 + 轻微震屏，连锁计数以毛笔字浮现于画面中央 |
| Boss 出场 | 战斗绘卷内演出：Boss 立绘从画面纵深处"显影"放大（显影动画 + 囃子音），背景画向两侧缓缓拉开 |

### 3.3 画面驱动的解密设计原则（硬性）

1. **零文字提示**：谜题线索只允许通过画面元素表达——水中倒影缺了一块、影子方向与光源矛盾、
   壁画上妖怪的眼睛跟着角色走、结界纹路有一处未闭合
2. **悬停只给感官反馈**：可交互物悬停时发出微光/轻响/呼吸起伏，**不弹文字标签**；
   玩家"看到"即"理解"
3. **交互即演出**：解开的瞬间必须有画面回报——纸门烧出洞、水面倒影拼合、阳光照进暗室
4. **提示系统保底**：卡关 90 秒后，画面内线索本身开始增强（光更亮、倒影闪一下），仍不给文字

## 四、世界观与角色

### 4.1 背景设定

山间的旧式小镇「**逢魔町**」——每天日落与黑夜交界的"逢魔时刻"，妖怪会自画中、镜中、水中走出。
主角一行是镇上承接"退魔委托"的**退魔寮**：白天勘验现场，逢魔时刻退治妖怪。

每一关是一幅"绘卷"：废神社、井户边的宅邸、纸门连绵的旧旅馆、河滩……

### 4.2 可操作角色（机制沿用 v2，人设日式化）

| 角色 | v2 原案 | v3 人设 | 机制（不变） |
|------|---------|---------|-------------|
| **凛音** | 前线术士 | 退魔剑士，沉默寡言的前武家出身 | 高 HP 抗恐惧，推拉距离 +1，可推重物 |
| **薄荷** | 侦察射手 | 忍足的小个子斥候，随身弹弓 | 移动零噪音，可远程触发机关（弹弓打铃） |
| **焰华** | 驱魔术士 | 持焰的巫女，衣袖藏火 | 点燃免 AP，火系卡伤害 ×1.5，净化灵气 |
| **清明**（原钟馗） | 封印师 | 阴阳师，持扇与符，寮主 | 结界阵布置，承受致命伤留 1 HP（每战 1 次） |

> 视觉重做：v2 的蒸汽朋克 + 道教元素全部替换为**日式和風**（见 §十四）。

### 4.3 敌人（Demo 5 种，机制沿用）

| 敌人 | 日式定名 | 行为模式 | 克制手段 |
|------|----------|----------|----------|
| 纸人 | **纸人形（しにんぎょう）** | 巡逻→发现→追击 | 火=恐惧，铃声=吸引 |
| 红衣女 | **红衣女郎（べにしとぎ）** | 被注视瞬移背刺，背对则静止 | 不看她、环境间接击杀 |
| 水鬼 | **河童（かっぱ）** | 潜伏水域→拖拽入水，离水变弱 | 引离水域、糯米减速 |
| 僵尸 | **跳尸（キョンシー）** | 直线跳跃 2 格越障 | 糯米减速、结界阻挡 |
| Boss | **棺守（かんもり）** | 棺中苏醒，两阶段：指挥→全图追击 | 结界封印击杀 / 伤害灌死 |

### 4.4 角色属性

- **恐惧值** 0–100：≥阈值失控 1 回合（沿用 v2 balance.json 外置数值）
- **灵感知**：探索模式下高灵感知角色能看出"画里的不对劲"（线索高亮半径）

## 五、核心系统

> v2 的 §5（多层地图、标签系统、互动系统、规则表、噪音、灵气、封印）**全部保留**，
> 本节只列横版化后的差异点。完整规则定义见 §十一数据格式。

### 5.1 舞台规则引擎（原地形系统）

标签 + 规则表机制不变，横版语义映射：

| v2 等距概念 | v3 横版语义 |
|-------------|-------------|
| 相邻 4 格 | 同层左右 ±1 列 + 上下相邻高度层 |
| 高台推落 | 高度差 ≥2 层被推下 → 坠落伤害（落地层差 ×3） |
| 水面导电 | 高度层 0 整层为水时，电系效果波及全水面（横版整行） |
| 火焰蔓延 | 同层每回合 ±1 列蔓延，**向上引燃**悬挂物（纸门、帘幕）速度 ×2 |
| 阻挡视线 | 纵深线不同 + 前景遮挡物 = 不可见 |

### 5.2 环境互动（探索模式，操作横版化）

以下操作发生在**探索模式**（角色在场景画中行走时）：

| 操作 | 输入 | 横版表现 |
|------|------|----------|
| 推 | 面对物体按确认 | 物体沿地面滚动/滑动（有惯性感），撞墙反弹一次 |
| 拉 | 面对物体按住后拉 | 角色后撤步，物体被拖近 |
| 推倒 | 长按 | 容器倾倒，内容物沿坡度向低层滚落（横版连锁核心） |
| 点燃 | 焰华免费 | 火焰沿纸门/帘幕向上窜的攀爬动画 |
| 敲钟 | 交互 | 声波从钟体向两侧扩散，画面可见的半透明波纹 |
| 换线 | 走到换线点 | 角色走"入"背景（缩小 20% + 降饱和），前景景物掠过 |

### 5.2b 战斗场景槽（战斗模式的"环境互动"）

战斗中**没有可走位的小人与可推的战场物体**；环境连锁改由**场景槽**承载：

- 每场战斗的背景画中预置 3–6 个**场景槽**（石灯笼、纸门、水钵、吊钟、注连绳…），
  作为画面中的发光描边元素呈现；槽位状态（完好/燃烧/破裂/鸣响中）直接画在背景上
- **场景卡**与部分技能卡指定槽位打出：「引燃」点在纸门槽 → 背景画中纸门真的烧起来，
  沿槽位连线向相邻槽蔓延（§5.1 规则引擎照常驱动，只是"格"映射为槽位邻接表）
- 妖怪受槽位状态影响（火焰槽相邻 → 恐惧；鸣钟槽 → 被吸引换位），
  AI 状态机照常运转，其"位置"= 立绘所在的**前/后排**槽位
- 推落/坠落在战斗中表现为「动摇槽」：满足条件的槽位倾倒，对当前排敌人造成坠落伤害并可能改变其排位列

### 5.3 噪音系统（横版传播）

- 沿 X 轴双向衰减 -1/格；高度差每 1 层衰减 -1；墙体遮挡 -2；水面传播不衰减且 **+1 格**
- 渲染：从声源出发的两组同心波纹（横版椭圆）， enemies 听到时耳侧闪现波纹图标

### 5.4 灵气密度（沿用 0–10 五档）

渲染变化：灵气 ≥6 时画面整体开始"不对劲"——背景绘卷的眼睛睁开、水面倒影与现实不一致、
色调向藤紫偏移；灵气 10（百鬼夜行）时全屏绘卷纹理蠕动。**灵气强度直接画在画面上**，HUD 只留一个小小
的墨点刻度。

### 5.5 结界封印击杀（沿用 v2 判定）

阵眼 ≥3 + 符纸 + 灵气 ≥6 + 目标在阵内 + 激活 → 即死。表现：五芒星结界从地面浮现，
金色墨线收拢，妖怪被"画"进符纸（掉落为图鉴残页）。

## 六、AI 系统

### 设计哲学（不变）

AI 是谜题的一部分，必须可预测：玩家读意图、规划反制、利用 AI 行为达成目的。

### 横版化差异

- **探索模式**：视线 = 2D 视锥（水平 ±sight_range 列 + 同层/相邻层），纵深线不同或被前景遮挡 = 不可见；
  听觉沿用 v2 阈值（音量 ≥3 → 搜索，≥5 且 fear_noise 高 → 恐惧）
- **战斗模式**：无战场走位，敌人"位置" = 前/后排槽位；攻击目标 = 我方出战角色立绘位；
  槽位状态（火焰/鸣钟/破裂）照常驱动 fear/rage/search 状态转换
- **意图预览**：敌人立绘旁浮动"心意气泡"——红的爪=攻击、黄的足=换位、橙的耳=循声、
  紫的焰=恐惧；战斗回合开始前全体气泡 1.2s 预览锁定
- 状态机（patrol/confused/rage/fear/search/chase/attack）与差异化行为（红衣女郎瞬移、
  河童水域拖拽、跳尸越障跳跃、Boss 两阶段 + 逃脱）**机制全部沿用 v2**

## 七、卡牌/技能系统

沿用 v2 框架（15 张卡 + 四角色环境被动），战斗全部经由手牌进行（见 §5.2b 场景槽）：

- 手牌常驻画面底部，**卡牌是主角级 UI**：大尺寸手绘卡面、打出时飞向画面中的目标
  （敌人立绘或场景槽）并化为实体效果
- 抽牌 = 从画面右缘"飞入"手牌（带纸牌破空音）；洗牌 = 牌背墨纹流动
- 卡位三分：**攻击卡**（指向敌人立绘）、**场景卡**（指向背景画场景槽：引燃纸门、摇响吊钟、
  推落石灯笼）、**结界卡**（指向地面阵眼，Boss 战终结手段）——"卡牌即退魔人的手"
- 焰华火系 ×1.5、凛音推拉 +1 等被动数值全部沿用 balance.json，不改平衡

## 八、Demo 关卡：「夜巡·逢魔神社」

### 场景

废弃神社的连续横版卷轴，约 3 幕（参道 → 本殿回廊 → 后院神木），每幕一卷轴，幕间以拉门转场。
画面驱动的谜题与战斗在同一场景内交替发生。

### 第一幕「参道」——解密教学（纯画面）

- 石阶前的**水面倒影**中，鸟居是完整的；现实的鸟居缺了一根柱——玩家注意到后走近，
  触发战斗：纸人形从残缺处入画
- 教学链（全部无文字）：倒影矛盾 → 靠近 → 发现 → 战斗触发 → 战后倒影恢复完整 → 道路开

### 第二幕「本殿回廊」——场景槽连锁教学

- 长回廊的战斗绘卷：纸门连绵（可燃槽）、吊钟（声源槽）、水钵（水源槽）、石灯笼（动摇槽）
- 目标：鸣钟场景卡引纸人形聚到前排 → 引燃纸门槽 → 火焰沿槽位连线蔓延 → 连锁教学，
  Boss 棺守在本殿前苏醒（战斗绘卷背景画向两侧拉开，Boss 立绘显影）

### 第三幕「后院神木」——Boss + 结界

- 神木四周天然阵眼 4 处，符纸散落于场景（探索时拾取，战斗中成为结界卡资源）
- Boss 棺守两阶段：阶段 1 指挥纸人形 + 固守；阶段 2 棺材破、全前排压制、向绘卷边缘逃脱
- 灵气 ≥6 时结界卡可激活阵眼槽 → 封印击杀；或伤害灌死

### 三阶段流程（沿用 v2 levelFlow）

侦查（回合 1–3）→ 惊醒（4–6，灵气 +2）→ 决战（7+），Boss 逃脱判定与失败文案沿用 level_director。

## 九、UI/UX 产品设计 ★（本章为 v3 最高优先级）

> 目标：UI 达到商业日式 2D RPG 水准（歧路旅人 / 伊苏式菜单质感）。
> 本章是设计与验收的唯一依据：任何新 UI 先对照 §9.3 设计令牌与 §9.5 组件规范。

### 9.1 设计原则

| # | 原则 | 含义 | 验收 |
|---|------|------|------|
| 1 | **画面优先，UI 退后** | HUD 默认低存在感；探索时除必要按钮外不常驻数值面板 | 截图里画面占比 ≥80% |
| 2 | **世界内 UI（diegetic）优先** | 能画进场景的不做悬浮 HUD：灵气画在色调里、谜题画在光影里、敌意图画在气泡里 | HUD 元素计数 ≤ v2 的一半 |
| 3 | **材质语言统一** | 全部 UI 材质 = 和纸 / 深胡桃木 / 金缮描边 / 墨线 | 任意两面板放一起不违和 |
| 4 | **每次输入都有回应** | hover 80ms 内给视觉回应，click 有 60ms 按压位移 + 音 | 无"死按钮" |
| 5 | **动效讲物理** | 面板如纸滑动、卡牌如羽落、墨水有重量 | 动效曲线符合 §9.6 |

### 9.2 画布与适配

- **基准分辨率 1920×1080**（16:9），UI 按 1080p 设计；1366×768 / 2560×1440 等比缩放
- Godot 项目设置：`viewport 1920×1080`，`canvas_items` 拉伸 + `expand`；安全区 48px（电视/刘海）
- 素材策略：所有贴图按 **2×（3840 资源）** 制作，运行时缩到 1×，保证 4K 输出不糊；
  九图边框用 `texture_margin_*`（Godot 4 语法），**禁止** patch_margin
- 布局网格：8pt 基础网格；内容最大阅读宽 960px；所有尺寸为 4 的倍数

### 9.5 组件规范（Component Spec）

**按钮 Button**（4 态 + 音效）：

| 态 | 视觉 | 动效/音 |
|----|------|---------|
| 常态 | 深木底 + 墨色描边 + 底部 3px 影边 | — |
| 悬停 | 金线从左"画"入（120ms）+ 文字 +2% 亮 | 木鱼轻响 |
| 按下 | 整体下移 2px，影边归零 | 笃（低） |
| 禁用 | 纸灰 40%，无悬停回应 | 无 |
| 危险 | 朱砂描边 + 悬停时墨纹爬升 | 警示音 |

**卡牌 Card**（战斗核心组件，尺寸 240×336 @1080p）：

- 结构：顶部 60% 手绘插画区 / 中部名称带（宋体 20px）/ 底部效果文本（黑体 14px）
- 左上费用：金色勾玉徽章（边缘厚度 3px）；右下稀有度角标
- 悬停：立起 1.15× + 顶部光源扫过（sheen, 240ms）+ 轻微 3D 倾斜（跟随鼠标 ±4°）
- 拖拽：离手后卡牌跟随光标带 8° 倾斜 + 投影加深；松手合法=飞出，非法=弹回（spring 回弹）
- 抽到手中：从右缘飞入 260ms（减速 + 轻微过冲），落位时纸响
- 打出消耗：勾玉徽章"碎裂"成墨点消散

**计量条 Meters**：

- HP 条：高 8px 圆角 4，苔绿（我方）/朱砂（敌方），伤害时白色"预扣段"先闪后扣（200ms）
- 恐惧条：高 5px 紫黑渐变，≥阈值时整条脉动 + 阈值刻度线
- 灵墨刻度：10 枚小墨点横排（直径 8px），点亮=墨色实心；≥6 时点内出现"眼白"微动画
- AP 勾玉：●满 / ◐半 / ○空，直径 14px，消耗时顺时针逐个碎裂

**飘字 Damage Numbers**：

- 伤害：朱红宋体 28px Bold，向上浮 40px 渐隐（700ms），暴击 36px + 墨点迸溅
- 治疗：苔绿；灵力：藤紫；恐惧：紫黑小字带轻微抖动
- 同屏同位置最多叠 3 条，溢出合并为一条大数字

**心意气泡 Intent Bubble**（敌意图）：

- 32px 圆形气泡悬浮头顶 48px，图标语义：红爪=攻击 / 黄足=移动 / 橙耳=循声 / 紫焰=恐惧 / 金符=特殊
- 预览锁定阶段：全体气泡按顺序"啵"地弹出（每 80ms 一个）+ 对应目标线画向落点
- 被打断（恐惧/混乱）时气泡碎裂动画

**对话框 Dialogue**：见 S8；组件要点：打字机光标是笔尖，跳过时全部显示 + 墨圈扩散。

**Toast/横幅**：顶部挂轴滑下（220ms），限 1 条，3s 自动收起；仅用于系统级通知（获得物品、阶段切换）。

### 9.6 动效设计（Motion）

**缓动曲线**：

| Token | 曲线 | 用途 |
|-------|------|------|
| `ease-standard` | cubic-bezier(0.4, 0, 0.2, 1) | 面板、转场 |
| `ease-decelerate` | cubic-bezier(0.0, 0, 0.2, 1) | 卡牌飞入、飘字 |
| `ease-spring` | 回弹 0.8（Godot `Tween.TRANS_BACK`） | 非法操作回弹、气泡弹出 |
| `ease-weight` | cubic-bezier(0.5, 0, 1, 1) | 重物落地、墨滴 |

**时长规范**：hover 80ms / press 60ms / 按钮态切换 120ms / 面板开合 220ms /
屏幕转场 350ms / 卡牌打出 300ms / 连锁慢镜 300ms（0.4× 速度）

**转场**：

- 场景切换（幕间）：拉门——两扇纸门从两侧合上（350ms, ease-weight）→ 切换 → 拉开
- 解密→战斗：墨线从四角画入成框（300ms），画面定格里战斗 UI 浮现
- 死亡/失败：和纸被朱砂墨浸透扩散（600ms）→ 落款"终"

**微交互清单**（必须全做）：按钮按下位移、卡牌悬停扫光、勾玉碎裂、墨点睁眼、
气泡啵出、卷轴展开、印章落下（盖章音 + 纸颤）、HP 预扣闪烁。

### 9.7 画质与渲染规范

**风格与分层渲染（每幕舞台）**——全画面手绘水彩，非瓦片拼接：

每幅画面是一张**完整的水彩画**（带纸质肌理、手绘线稿与颜料沉淀），按横向卷轴切成若干
"镜头段"（每段 ≥1920px 宽，段间手工做过渡衔接，**禁止暴露重复贴图**）。
视差通过同一张画的手绘分层切片实现，各层规格：

| 层 | 内容 | 视差系数 | 规格 |
|----|------|----------|------|
| L0 天空/远景 | 逢魔时刻的渐变天、远山、町剪影 | 0.1 | 每镜头段 2400×1080 手绘切片 |
| L1 远景建筑 | 町屋屋顶、神社本殿、树影 | 0.25 | 每镜头段 2400×1080 手绘切片 |

**角色规格**（大比例人物，以基准图为尺）：

## 十二、算法细节

### 12.1 噪音传播（横版版）

```
func propagate_noise_side(origin, volume) -> Dictionary:
    # 沿 X 轴双向队列扩展
    queue = [(origin, volume)]
    while queue:
        (pos, vol) = queue.pop_front()
        if vol <= 0: continue
        result[pos] = max(result.get(pos, 0), vol)
        for dir in [-1, +1]:
            nxt = pos + dir
            decay = 1
            decay += abs(height[nxt] - height[pos])      # 高度差每层 -1
            decay += 2 if wall_between(pos, nxt) else 0
            if has_tag(nxt, "liquid"): decay = 0; vol += 1   # 水面放大
            queue.append((nxt, vol - decay))
```

阈值沿用 v2：音量 ≥3 → search；≥5 且 fear_noise ≥0.5 → fear。

### 12.2 视线判定（2D 视锥）

```
可见(unit, target) =
    同纵深线
    AND 水平距离 ≤ sight_range
    AND |高度差| ≤ 1 层
    AND 之间无 blocking 标签物体
    AND 目标不在前景遮挡物（L3 遮挡列表）之后
```

### 12.3 灵气 / 封印 / AI 状态转换

全部沿用 v2 §12.2–12.4 公式，仅"相邻格"定义按 §3.1 映射（同层 ±1 列 + 相邻高度层）。
