# v2 架构说明 — 封魂·蒸汽道术

> 本文档供 AI 编码助手与开发者阅读。描述 v2/v3 架构（图块大地图探索 + 卡牌战斗 + 多结局）的
> 目录结构、模块职责、数据流。v2 与 v1（旧等距战棋）完全隔离。

## 一、项目定位

- **类型**：图块大地图探索（64×64）+ AVG 对话 + 卡牌战斗（StS 式）+ 多结局 RPG
- **题材**：蒸汽朋克 × 道家僵尸（蒸汽道术）
- **引擎**：Godot 4.6（**forward_plus / Vulkan** 渲染器）
- **核心循环**：标题 → 章节对话 → **64×64 网格大地图探索**（移动/互动/拾取/钥匙门/遇敌）→ 卡牌战斗 → 选牌奖励 → 回地图 → 传送门 → 多结局

## 二、素材管线（切割 → manifest → 投入系统）

```
tools/build_asset_pipeline.py（Python + Pillow，一键全量）
  1. 生成源图（程序化"建模"）：10 种图块 atlas(8×2×32px)、UI 9-slice 源图、道具精灵
  2. 切割：atlas → 独立图块 PNG；UI sheet → panel_main/panel_dark/button
  3. 产出清单 data/v2/asset_manifest.json（所有资产的唯一登记处）
  4. 生成 64×64 程序化地图 data/v2/maps/map_64.json（seed 固定，可重复）
  5. 生成 UI 主题 data/v2/ui_theme.json（9-slice 边距像素级配置）

运行时：
  AssetRegistry（scripts/v2/core/asset_registry.gd）
    ← 读 manifest，get_texture("tiles/wall") / get_tile_atlas_coords("door")
  TileMapV2（scripts/v2/core/tile_map_v2.gd）
    ← 读地图 JSON，运行时从 atlas 建 TileSet（NEAREST 像素风），填 64×64 格子
    ← 逻辑查询：is_walkable（墙/坑/锁门/敌人占位）、物件索引、BFS 可达
```

**新增素材的标准流程**：改/加 `build_asset_pipeline.py` 里的绘制函数 → 重跑脚本 → manifest 自动更新 → 游戏内经 AssetRegistry 引用。禁止在 GDScript 硬编码资产路径。

## 三、地图玩法（64×64，全部经 map_test BFS 验证可达）

| 玩法 | 规则 | 代码入口 |
|---|---|---|
| 网格移动 | WASD/方向键，0.13s 滑动，图块碰撞 | explore_scene._try_step |
| 墙/坑阻挡 | `wall/void/pit` 不可走 | TileMapV2.is_walkable |
| NPC 互动 | 4 邻格按 E → 对话节点（on_trigger） | _try_npc_interact |
| 敌人遇敌 | 走入敌人格 → 卡牌战；占位阻挡通行 | _start_encounter |
| 道具拾取 | 踩上道具格 → set_flag + 可选 give_card | _pickup_item |
| 钥匙封印门 | `D` 格 requires_flag（如 has_key），锁定提示 | TileMapV2.is_door_open |
| 传送门出口 | `P` 格 + requires_flag → 章节 complete | _try_portal |
| 拾取→战斗闭环 | `card_*` 旗标 → init_battle 并入牌池 | GameStateV2.init_battle |
| 位置保留 | 对话/战斗返回回到原图块 | GameBridge.explore_return_tile |

## 四、高精度 UI（JSON 驱动 9-slice）

- `data/v2/ui_theme.json`：面板/按钮的源图、9-slice margins、content margins、modulate 全部像素级配置
- `UIThemeFactoryV2`（scripts/v2/ui/ui_theme_factory_v2.gd）：`panel("main")` / `apply_button(btn)` / `apply_panel(ctrl)`；贴图缺失自动回退 StyleBoxFlat（色板仍来自 JSON）
- 已应用：CombatantView（main 面板）、CardView（按钮三态）、DialogPanel、标题/奖励屏按钮
- **改 UI 只改 JSON**，无需动 GDScript

## 四、核心数据流

### 4.1 章节流转

```
title → SceneRouter.start_new_game()
       → NarrativeState.wipe() + enter_chapter("chapter_1","start")
       → go_dialog("chapter_1","start")
          → dialog_scene._ready() 读 GameBridge.next_chapter_id/next_node_id
          → ChapterLoader.load_chapter() 读章节 JSON
          → _render_current_node() 按 node.type 分发：
              dialog  → 渲染背景/立绘/文本/选项，玩家选择 → set_flag → _navigate(next)
              battle  → SceneRouter.go_battle() → card_battle_scene
              ending  → SceneRouter.go_ending() → ending_scene
```

### 4.2 卡牌战斗

```
card_battle_scene._ready()
  → GameStateV2.init_battle(["rinne"], enemy_ids)   # 从 GameBridge 读敌人列表
  → state.start_player_turn()                        # 抽牌 + 生成敌人意图
  → _refresh_all() 渲染敌人区/玩家区/手牌/灵气

玩家点手牌 → _on_hand_card_clicked(index)
  → state.can_play_card(card_def)? 
  → 若需选目标：高亮手牌，等玩家点敌人立绘
  → _play_selected_card(target)
     → state.spend_qi(cost)
     → resolver.play_card(card_def, target, state, player_entry)
        → _apply_effect() 应用伤害/治疗/护盾/tag
        → combo_engine.try_trigger(card_tags, target, context)  # ← 项目灵魂：连锁
     → _log_combo_result() 战斗日志显示 combo 触发
  → 检查胜负 → won/lost 信号 → 回 dialog_scene 渲染 on_victory/on_defeat

玩家点"结束回合" → _on_end_turn_pressed()
  → state.end_player_turn() 弃手牌 + tick tags
  → state.start_enemy_turn() → _execute_enemy_intents() 执行每个敌人意图
```

### 4.3 Combo 引擎（保留旧 terrain_system 灵魂）

```
CardResolverV2.play_card() 应用完卡牌自身 effects 后：
  对每个主目标调 combo_engine.try_trigger(card_tags, primary_target, context)
    → _drain_pending()（重入保护 + 队列）
    → _process_one() 遍历 _combos 规则表
       → _conditions_met(trigger, card_tags, target)
          · 检查 card_tag 是否在卡牌 tags 里
          · 检查 target_tag 是否在目标 tags 里（target.has_tag()）
       → _resolve_spread() 解析 spread 字段（all_enemies / enemies_with_tag:X）
       → 返回 affected_targets 列表 + effects 数组
```

例：敌人带 `wet`，玩家打出 `steam_valve_release`（tags 含 `fire`）
→ 匹配 `steam_explosion` 规则
→ spread `enemies_with_tag:wet` 蔓延到所有带 wet 的敌人
→ 每个敌人受 8 点 magic 伤害 + 移除 wet + 施加 scalded 2 回合

## 五、数据 Schema 要点

### 卡牌 `data/v2/cards.json`

- `target_type`：`self` / `single_enemy` / `single_ally` / `all_enemies` / `all_allies`（无格子语义）
- `tags`：combo 引擎匹配用（如 `fire` / `lightning` / `glutinous`）
- `effects`：`deal_damage` / `heal` / `gain_shield` / `apply_tag` / `apply_status` / `draw_cards` / `gain_qi` / `lifesteal`

### Combo `data/v2/combos.json`

- `trigger.card_tag` + `trigger.target_tag`：双重条件
- `result[].spread`：`primary` / `all_enemies` / `all_players` / `enemies_with_tag:X` / `players_with_tag:X`

### 单位 `data/v2/units.json` / `enemies.json`

- `sprites.battle` / `sprites.portrait`：数据驱动美术路径（告别旧版文件名约定）
- `animation_profile`：`breath` / `float` / `stiff`（Tween 动画模式）
- `tags`：永久标签（如 `jiangshi` / `undead` / `daoist`），combo 匹配用
- `intent_profile`（敌人）：意图 AI 配置（behaviors / attack_damage / target_priority）

### 章节 `data/v2/chapters/*.json`

- 节点图结构，`entry` 指向入口节点
- 节点 `type`：`dialog` / `battle` / `ending`
- `choices[].set_flag`：写入 NarrativeState.flags，影响结局判定
- `battle.on_victory` / `on_defeat`：战斗结果回跳节点

### 结局 `data/v2/endings.json`

- `condition`：flags 上的 AND 条件
- `priority`：高优先级先匹配

## 六、与 v1（旧战棋）的关系

- **完全隔离**：v2 所有代码在 `scripts/v2/`、`scenes/v2/`、`data/v2/`，v1 代码原样保留作参考
- **复用的 v1 资产**：`Deck`（牌组）、`StatusEffectManager`（状态）、`JsonLoader`（JSON 加载）、`EventBus`（autoload 保留）、`shaker` 插件、字体、`project.godot` 渲染配置
- **未复用**：`GameMap` / `Pathfinding` / `TerrainSystem`（已由 `ComboEngine` 取代）/ `AIController`（已由 `EnemyIntentAI` 取代）/ `NoiseSystem` / `InteractionSystem` / `battle_scene.gd`（已由 `card_battle_scene.gd` 取代）
