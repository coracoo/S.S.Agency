# v2 核心系统 → v3 移植评估（2026-09-29）

> 结论先行：**不做整体移植，做语义重实现**。v2 的三个核心系统（noise/spirit/ai_controller）
> 都建立在**网格战棋**之上（BFS 传播、曼哈顿距离、格子寻路、巡逻路径），与 v3
> 「横版画面驱动 + 场景槽 + 意图公示」的架构根本冲突；但其**设计意图**大多已被 v3
> 以更适合画面驱动玩法的方式覆盖，少数遗漏点以 v3 语义补齐更划算。

## 一、逐系统评估

### 1. 灵气密度（spirit_system）— ✅ 核心已等价覆盖，补两个遗漏

| v2 能力 | v3 现状 | 结论 |
|---|---|---|
| 0–10 五档（weak/normal/reinforced/rage/百鬼夜行） | 已移植：tier_attack_mult 0.7/1.0/1.3/1.5（battle JSON `spirit` 节数据驱动） | 不移植 |
| 封印需灵气≥6（tier REINFORCED_MIN） | 已移植：`seal_rule.min_spirit` | 不移植 |
| 尖啸/回合成长改变密度 | 已移植：`per_turn` + `howl_spirit`（敌方 pattern 驱动） | 不移植 |
| move_delta（灵体弱/强化移速±1） | 未移植 | **不移植**——v3 无网格移动，敌人位移走演出动画 |
| player_turn_damage（高灵压回合开始伤害玩家） | 未移植 | **建议补**（P2）：灵气≥8 时玩家回合开始受 1–2 点灵压伤害，给「尖啸堆灵气」的敌方策略真实威胁，数据放 battle JSON `spirit.pressure_damage_from` |
| 百鬼夜行（密度10 全体 rage） | 无（v3 单场单敌轮换，无"全体"概念） | **不移植**，等价物是 berserk 档 ×1.5 已在 |

### 2. 噪音系统（noise_system）— ❌ 不移植，语义已被重定义

- v2 是**网格 BFS 传播**（每格 -1、阻挡 -2、水面放大），服务「听觉阈值驱动 AI 搜索」——
  这是网格潜入玩法的机制，v3 战斗没有网格、没有搜索行为。
- v3 的「鸣钟」语义已重定义为**眩晕 + 惊焰清场**（画面驱动：声浪具象为灭火连锁），
  与 v2 `object:bell_rung` 完全是两个设计。
- **唯一可留的遗产**：若未来 stage（横版探索）要做潜入/惊动玩法，噪音应以
  **横版距离线性衰减 + 遮挡判定**重实现（几行代码），而不是搬 BFS。
  评估：留作 stage 阶段需求，不进入战斗。

### 3. AI 控制器（ai_controller）— ❌ 不移植，意图系统已是 v3 的等价升级

v2 状态机（patrol/confused/rage/fear/search/chase/attack + Utility 选点 + A*）依赖
网格位置、占位、寻路；v3 用 **pattern 轮转 + 回合开始意图公示 + 状态覆盖
（眩晕 > 暴走 > 恐惧降级猛扑）**（INTO THE BREACH 式），这本身就是 GDD 为
画面驱动战斗做的再设计，可预测性比状态机更适合卡牌对战。

逐状态对照：

| v2 状态 | v3 等价物 | 缺失度 |
|---|---|---|
| rage（执念威胁触发） | `berserk` 意图（灵气≥8 或 pattern 指定，×1.5） | 已覆盖 |
| fear（恐惧） | 遇火 `fear_attack_mult` ×0.5 + 猛扑降级 | 已覆盖 |
| confused（符纸随机移动） | **无** | **建议补**（P2）：「迷魂符」卡——敌方下回合意图随机化并降攻，画面表现为立绘晕圈 |
| stun（鸣钟） | `stun` 意图（即时结算，已修） | 已覆盖 |
| patrol/search/chase + 寻路 | 无 | **不移植**——无网格；位移演出由 `pounce/leap` 意图承担 |
| obsession（执念对象被威胁→rage） | **无** | **建议补**（P3）：enemy 数据加 `obsession` 字段（如棺守执念「棺」：玩家点燃特定槽时强制暴走），把 v2 最有味道的行为差异带进 v3 |
| Boss 两阶段/逃脱 | `seal_guard` 破阵（本次新增） | 已覆盖且更贴卡牌 |

## 二、数据缺口（独立于移植，顺手记）

1. **`spilled`（水钵倾覆）有完整结算代码但没有任何产生途径**——无卡牌/交互能令槽变
   spilled。建议补一张「倾覆」场景卡（或探索段水钵交互带入战斗），让"水克火"的
   反制链闭环（现为鸣钟独揽灭火）。
2. `stun_skip`（v1 字段，僵尸类免疫眩晕）在 v3 代码中未消费——棺守已设 false，
   普通纸人形设了 true 但没生效。要么接上（`_enemy_stunned` 判定时查），要么从数据删除。

## 三、结论与优先级

| 优先级 | 事项 | 性质 |
|---|---|---|
| P1 | 不移植任何 v2 系统本体；战斗深度走 v3 意图体系自己的路 | 决策 |
| P2 | 灵气高压伤害（`pressure_damage_from`）+ 迷魂符卡 + `stun_skip` 接线 | 小步代码+数据 |
| P3 | obsession 执念字段（棺守：棺被点燃→暴走） | 机制扩展 |
| P4 | stage 潜入玩法的横版噪音衰减（若做） | 新需求 |

**风险说明**：ai_controller 770 行、noise 145 行、spirit 304 行均为 `class_name` 纯逻辑类，
不引用即无编译开销；v1/v2 场景文件保留在仓库中不影响 v3 运行，无需删除。
