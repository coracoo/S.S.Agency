# 验收矩阵 D 项操作清单：卡池、预览、模型与视觉（交给测试执行者）

2026-10-13。对应[试玩反馈验收矩阵](2026-10-08-playtest-remediation.md) §5 D 项。**前置：A–C 项已通过，代码为 `main` ≥ `4708878`。** 隔离、外部锁与证据目录约定同 [A项操作清单](2026-10-11-parse-check-runbook.md)。

本项验收角色专属卡池（build2，60 卡 / 42 主动 / 18 被动，复用 24 招式 / 28 美术变体）。核心原则：**模型层拒绝优先于 UI 隐藏**——所有归属/形态/互斥校验必须在直接提交路径上验证，不能只看面板不显示。

## 第 1 步 卡归属与形态校验

- 六人物 / 七形态遍历全部 60 张卡：每张卡的归属人物、允许形态与 `loadouts.json` 定义一致（`owner_identity`、`allowed_forms`、`visual_form` 对应关系）。
- **直接提交路径**（绕过 UI）必须拒绝：外人物卡、错误形态卡、直接提交 build1 旧构筑（`build.version != 2` 拒绝）。
- 通用指令不得被"专属卡"误伤：物理普攻、防御、道具对所有角色可用；**术法普攻受双条件约束**（角色身份为焰华/苏合/清明 且 当前武器带 focus 标签），两类条件分别摘除验证（有 focus 武器的凛音不能术攻，无法器的苏合也不能）。
- 既有入口：`python tools/rpg/run_checks.py --suite all`（含 `test_loadouts.gd`、`test_loadout_conditional_modifiers.gd`）、`python tools/campaign/run_act_one_checks.py --script res://tools/campaign/test_loadout_menu.gd --output-dir <证据>`（菜单 45 断言的当前版重跑）。

## 第 2 步 互斥、容量与事务

- 同一招式的原式与变式不能在两个槽同时装配（UI 与模型 `derive` 双层都验）；容量（主动 4/容量 10、被动 2/容量 4）与武器标签仍拒绝非法装配。
- 事务路径：合法换武器、换卡、取消（武器与卡一起放弃）、收藏不足、写入失败——存档内容要么完整提交要么不变。
- 既有入口：`--script res://tools/campaign/test_loadout_campaign.gd`（事务）、`test_loadout_battle.gd`（实战装配）、`test_loadout_initiative.gd`（速度轮序）。

## 第 3 步 焰华双形态

- 剑/法各 6 候选；法形未解锁时只能编辑备用组与预览，不能进入实战。
- 切形态：不恢复资源、不清冷却、不增加行动；两形态共享本人 3 张被动。
- 焰华剑式卡使用 `homura_sword` 美术变体与本人卡 ID，**不得借用凛音卡或 `rinne` 变体**。

## 第 4 步 派生一致性

- 卡位详情、装配预览、行动预览、真正执行的 MP/冷却/效果、普通与条件伤害系数、持续时钟——五处使用同一派生结果（`SKILL_DERIVATION_VERSION=3`）。
- 重点卡叠加与边界 clamp：疾切、短援、凝霜、续守、强引（含系数上下限、冷却下限、持续上下限）。
- 玩家可见名称显示卡片名（变式不显示基础招式名）；日志/回放可保留基础 ID。
- 旧回放指纹（v2 及更早）必须明确拒绝或报告差异，不能冒充同版本。

## 第 5 步 视觉变体

- 原 24 招式 / 28 美术变体逐项合法触发（含朝向、触点、免疫、护盾、倒地、取消生命周期）。
- 动作与 hash 门禁按 `tools/characters` 既有统一入口运行；**不得更新批准美术哈希来绕过失败**。
- 装配面板与货架截图：`capture_loadout_ui.gd`；战斗视觉事件：`run_presentation_checks.py` 与 `--dual` 重跑。

## 通过标准（全部满足才进 E 项）

- [ ] 60 卡归属/形态遍历表完成，直接提交路径拒绝全部生效
- [ ] 互斥/容量/事务全过，含失败路径
- [ ] 焰华双形态与切形资源规则正确
- [ ] 五处派生一致，重点卡 clamp 有实测值
- [ ] 24/28 视觉变体逐项通过，hash 门禁无放行

任何失败：归档并回报改造方；修复后从第 1 步重跑。
