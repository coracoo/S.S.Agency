# 验收矩阵 C 项操作清单：战斗布局与接地（交给测试执行者）

2026-10-13。对应[试玩反馈验收矩阵](2026-10-08-playtest-remediation.md) §5 C 项。**前置：A、B 项已通过，代码为 `main` ≥ `4708878`。** 隔离、外部锁与证据目录约定同 [A项操作清单](2026-10-11-parse-check-runbook.md)。

本项覆盖"UI 过大、敌我太近"与"纸片与背景突兀"两项反馈的验收。改造内容：技能按钮 336×132→288×88、顶栏/状态卡/意图标签压缩、人物比例 190→165 px/m、双方出生位拉开、编队取景只按待机边界、受光权重 0.65→0.82、高清纹理线性采样、无效材质属性修正。

## 第 1 步 多分辨率布局截图

对 **1920×1080、1366×768、1280×720、超宽屏** 各执行一次图形化战斗截图（`run_act_one_checks.py --graphical` 自带 `--resolution` 参数，参照其用法）：

- 使用既有截图工具：`tools/campaign/capture_battle_world.gd`、`capture_battle_plain.gd`、`capture_combat_skin.gd`（经 `python tools/campaign/run_act_one_checks.py --script res://tools/campaign/<工具>.gd --graphical --output-dir <证据目录>` 运行）。
- 每个分辨率核对：待机全身可见、血条/MP 条不溢出、技能按钮文字不被通用皮肤最小尺寸撑回（288×88）、行动预览三行可读、敌意图标签不截断、顶部轮序完整、键盘焦点可达全部按钮、T/道具/返回标题可用。
- 重点核对旧疑点：敌意图标签收到 184/286px 后长文本是否溢出——溢出即回报改造方，不得按旧 356px 标准放宽也不得删检查。

## 第 2 步 阵型与多敌阵列

- **七形态**（含焰华双形态）分别进战，核对待机间距可读、敌我不过分贴近。
- 覆盖：双敌、五夜 Boss、后章多敌阵列（含纸兵/灯影混编）。
- 近战角色前移攻击不越出屏幕、归位一致；长柄武器（戟）待机时不再把整个队列挤向敌方——这是 `projected_bounds(resting_only=true)` 的新行为，若待机间距仍被武器伸展推着走即回归。
- 每个场景归档截图。

## 第 3 步 受光、脚影与接地

- 对照受光开/关、亮地/暗地、阶梯脚影、跳跃起落各截一组。
- 判据：
  - 白衣与深发不过暗、不糊成一片；人物不能被压黑来冒充与背景融合；
  - 边缘线性采样不露出原 RGB 白边（重点看岑照白衣与发丝）；
  - 脚影与显示位置同步（移动/跳跃/斜坡上均贴脚）；
  - 仍为平面表现的部分单独记录，不得记为"已三维化"。
- 历史 66 次无效材质属性警告（`rim_color`/`rim_size`/`rim_fade`/`specular`）必须保持清零（A 项日志基线已查，此处战斗场景复查）。

## 通过标准（全部满足才进 D 项）

- [ ] 4 种分辨率截图齐，第 1 步核对项全部通过
- [ ] 七形态 + 双敌/Boss/多敌阵列间距与归位正确
- [ ] 受光/脚影对照组归档，无压黑、无白边、脚影同步
- [ ] 意图标签截断旧疑点已定性（通过或回报）

任何失败：截图与日志归档，回报改造方；修复后从第 1 步重跑。
